# 最终目标导向的完整产品审计

日期：2026-09-07  
对象：当前集成工作树、Windows 已安装版本的近期验证证据、Windows 正式应用库本轮只读统计。  
性质：功能与架构审计、下一轮研发基线；不是新的完成声明，也不是本轮代码修复记录。

## 1. 结论与责任纠偏

**目前尚未达到“能够持续观察、理解两个孩子，主动组织学习，并凭可靠反馈持续改善教学和计划”的最终目标。不是只差孩子到场测试，而是仍有确定的执行架构、评价逻辑、课程供给和反馈学习缺口。**

现有成果不是空壳：语音、设备桥、Tutor、错题本、计划、记忆、报告、证据追踪、模型网关和 Windows 安装都有实际代码及不同层级的验证。但它们尚未成为一个可靠工作的整体。

之前工作的主要偏差，是把“某个意图正确路由、某个模块跑通、某组测试通过”逐渐当成“孩子的完整事情能办成”，并把部分尚有工程缺口的功能写成“只待孩子校准”。这份审计纠正该判断。

不提供一个未经定义和测量的总体完成百分比。当前总账的 20 个功能域均为 partial，0 个达到六层 complete；这不表示代码完成度为零，也不能据此推导代码完成了百分之多少。更有意义的结论是：**底层组件已经较多，持续执行、可靠教学评价和数据驱动改进这三条主干仍未贯通。**

本次不改运行时代码、不部署、不调用付费模型、不启动原子提取或监控。后续方案可以替换原设计的实现方式，不删除最终功能范围。

## 2. 最终产品究竟要完成什么

主要用户是南京四年级、初三两名孩子；家长是目标协商者、反馈者和必要时的审核者，不是每天替系统操作的程序管理员。

完整的一天应当是：

1. 孩子自然说话进入学习，系统知道是谁、昨天停在哪里、今天还有哪些未兑现事项。
2. 结合课堂口述、作业要求、书页与实际课程进度，区分已知事实、遗漏和待确认内容；不能用课标“脑补”成老师实际讲过的事实。
3. 综合学校任务、截止时间、薄弱点、长期目标、可用时间和当前负担，协商今天的可执行计划。
4. 学习中持续观察书页和书写进度，听懂追问、纠正、插话、指代与临时变化；不要求孩子迁就页面或预制命令。
5. 遇到困难，先确定具体题目和孩子原始作答，再鉴别错因、选择教学方法、边讲边演示，最后用适当的新问题检验。
6. 休息、活动、求助和娱乐有边界，能回到原任务；提醒有依据，不抢话，不把离座直接解释为不认真。
7. 结束时保存真实完成与未完成内容、待核实薄弱点及后续复测，关闭应关闭的采集，形成家长可执行的报告和沟通建议。
8. 第二天及后续周月，根据独立作答、迁移、延迟保持、习惯执行和家长行动结果调整计划与策略；证据被纠正后能够撤销错误结论。

长期目标包括校内全学科学习、PET、竞赛数学思维、初三备考、独立学习习惯和健康陪伴。提分是要验证的结果，不能由对话次数、学习时长或模型自评分替代，也不能保证获奖或通过考试。

已退出当前范围：可销售吊坠、专用云台底座、定制 Android 平板、学校教师触点。当前硬件基线是家用 Windows 电脑、摄像头、高拍仪及麦克风；这些旧产品方案不应继续消耗主线研发资源。

## 5. 可定位的结构与逻辑缺口

### A. 智能体办事能力

**G01 / P1：执行完一步，缺少通用的“看结果再决定”循环。**

`agent_runtime.py:2052` 每个计划插入 index=0；`complete_turn_execution:2076` 更新步骤与计划后返回。`agent_orchestrator.py:2427` 消费该回执。已有错题/Tutor 专用后续和主动提醒，不能说系统完全没有串联；但未形成全能力通用的目标推进器。单步滚动规划是可保留的，不能以生成大段多步 JSON 代替执行循环。

验收：一次提出“把今天没懂的补上，再安排复习”，系统按结果持续推进，直到需要孩子回答、授权、真实阻塞或目标达标；取消/重启不丢失或重复执行。

**G02 / P1：业务执行所有权仍在页面阶段中。**

`SessionWorkspace.tsx:472,4225`、`ContinuousDocumentMonitor.tsx:493`：StudyStep、持续观察及部分接收器依赖 study 阶段。跨阶段拍题/Tutor 有补齐，但尚非全部业务全阶段可调度。

验收：报到时看题、学习中补作业、休息时问刚才的问题，自动准备上下文并返回原事；隐私暂停和权限不得被绕过。

**G03 / P1：全语音覆盖不能靠隐藏按钮。**

`styles.css:96` 隐藏按钮/表单；`agent_runtime.py:375` 及 [语音能力矩阵](<本机用户目录>/Documents/学生教育/docs/development/2026-09-07-voice-capability-matrix.md:90) 仍有任意条目修订、删除、跨阶段重排和家长入口交接缺口。

验收：自然定位“刚才第二项”、澄清、修改、撤销，相关计划/义务一起更新；所有孩子日常功能都有可完成的语音路径，不要求精确命令。家长鉴权不是孩子可绕过的普通能力。

**G04 / P1：发言入口分散，错误告知又可能被隐藏。**

`ContinuousDocumentMonitor.tsx:432` 取景提醒发送事件，`SessionWorkspace.tsx:1337` 接收并播报；`agent_runtime.py:1134` 等待回答会挡住另一类提醒。`LocalInputs.tsx:631,729` 的部分失败只设置 error，而 `.agent-voice-controls` 被隐藏。

验收：孩子回答、讲解、遮挡、休息到时并发时有统一优先级/延期/失效规则；拒收、积压、断网可感知，不静默丢话，不因错误播报触发回声循环。

**G05 / P1：保存回合记录不等于恢复当前学习任务。**

`agent_runtime.py:1085` 通用运行步骤重启转 failed；`agentWakeResumePrompt.ts:9` 却采用泛化接续话术。已有 Tutor/档案切换恢复日志应保留。

验收：在收音、等回答、设备执行、评分、播报、回执任一位置中断，恢复具体题目、材料版本、问题、已播段和下一动作；对不确定的外部副作用先核对，不盲目重放。

### B. 判断是否学会

**G06 / P1：错因的否定表达会被关键词误判，并改变训练门槛。**

`agent_orchestrator.py:3055` 将含“粗心”的句子归 incidental，未处理否定；“不是粗心，我不知道为什么错”也会命中。`mistake_book.py:34` 的 incidental 只要求一次 repair_check，而 unknown 包含延迟检查。

验收：否定、未知、混合原因不能自动降低要求；先提出待证假设，用能区分概念、提取、读题、方法和执行失误的问题验证。

**G07 / P1：错题门槛读取与可靠掌握投影不一致。**

`mistake_book.py:826` 按作答正确、独立、无提示、阶段时间和不同题目 ID 计数，没有在该读取处重新消费来源撤回、评分资格、置信度和题目等价身份。与 `learning_obligations.py:152` 的严格投影不同。正常写入已有前置守卫，不能据此断言任意不合格输入都可从公开接口写入；风险在历史数据、后续撤回和跨模块投影一致性。

验收：低置信、撤回、来源失效、同题换 ID 均不能推进；曾通过的门槛能因证据修订重新降级；错题本、孩子模型、计划和家长报告得出一致结论。

**G08 / P1：单次回答正确与整个学习目标完成缺乏逐标准覆盖约束。**

`learning_outcome_evaluator.py:245` 正确允许一轮只回答当前问题；`:348` 又主要按阶段、independent 和模型置信度转换到 transferred/retained/completed。已有复述/辅助拦截，迁移后安排三天复测，`agent_capability_executor.py:622` 的激活器检查到期、归属及来源撤回；下游还将该结果区分为模型评价证据，不冒充验证掌握。这些保护必须保留。缺口是每项成功标准的覆盖记录、验证过的新题身份与目标关闭条件未统一；本轮静态审计没有复现完整接口提前 retained，不能将此风险表述成已发生的生产事实。

验收：目标含多个标准时，答对一项不能关闭整个目标；换表述的同题不能冒充迁移；无足够延迟证据不能说已保持。模型置信度不是经过校准的正确概率。

**G09 / P1：开放表达与推理过程还缺可进入可靠反馈的评分路径。**

`learning_obligations.py:152` 可靠 exact 入口只接受 local_exact_v1，排除 keyword/task_points/PET reference rubric；`learning_state.py:1147` 的开放参考分不能承担掌握认证。保守拒绝是正确的，但不能长期以此替代正式评价能力。

验收：版本化分维度 rubric、必要时本地数学验证器/证据复核、对同义表达和过程错误的反例集；题干/原答案确认后才评分。可靠结果能影响孩子模型和计划，不可靠结果保留假设且可复核。

**G10 / P1：专项阶段和弱项排序容易被旧参考评估支配。**

`specialized_program.py:694` 有 assessment 即优先于当前独立作答聚合；阶段按覆盖率/均分划分。代码明确标注参考分不等于掌握，这个边界应保留；问题是旧参考值仍可能影响训练重点，进阶也未充分绑定迁移/延迟条件。

验收：旧高分后的新连续失败改变优先级；记录评估时效、题目难度、证据冲突和阶段条件，不能把参考阶段名称写成已获能力。

### C. 计划与内容供给

**G11 / P1：长期目标更多是周配额，尚非能力路线倒排。**

`goal_program.py:163` 周期沿用 default_weekly_minutes/sessions；`:622` 只有 horizon.target_date 才计算剩余时间。“六年级上学期”需要结合入学/学期信息明确日期及不确定性，再建立前置能力和阶段达标路线。

验收：同目标不同基线/剩余时间产生不同路线；连续失败或时间不足会重排、解释风险和协商取舍，而非增加压力或仅更改计划标题。

**G12 / P1：PET 训练可能被到期词汇挤占。**

`repository.py:2083` 有到期词卡即使用 PET 时间段，否则按完成次数轮换活动。缺按听说读写弱项分配机会及欠练保护。

验收：连续有词卡到期的两周内，薄弱口语/听力仍得到训练与复测；专项与校内作业冲突有可解释的延期，不偷偷漏掉长期义务。

**G13 / P1：资料规模与可执行课程能力脱节。**

正式库 10,091 个资源对应 curriculum_capability=0；`curriculum_internalization.py` 已有构建、诊断蓝图及审核逻辑，但无本库产物。`knowledge_graph/local_course_context.py:21` 当前主路径是词项/BM25 检索、短片段比较，明确标为非验证课标对齐。

验收：按两孩子实际教材版本、学期、学科建立覆盖表，每个教学单元有目标、前置、解释材料、鉴别题、练习/迁移、评分依据、出处及审核状态；缺口可见。全文检索只作召回，不冒充课程能力。

**G14 / P1：本地课程知识与云端教学决策尚有断层。**

`agent_orchestrator.py:1448` 本地原子上下文在云端规划后处理，主要提供本地假设/追问和计数；cloud_transmission_allowed=false 必须继续遵守。仅换更强云模型不能自动让它具备本地未传输的知识。

验收：本地课程服务能输出有来源和资格的教学决策，由 Runtime 组合使用；明确云端可见的任务、经允许的抽象指导和禁止外传的证据。不得为改善效果擅自上传本地原子节点/关系/来源、教材 PDF 或家庭画面。

**G15 / P1：持续题目供给在正式库有实际阻塞。**

61 个 blocked job 中 56 个缺本地模板、5 个阶段不支持；不能把“有供应器”当成“有足够高质量题”。104 个 active 题目不足以证明全学科和三专项完整覆盖。

验收：按能力域、年级、难度、训练阶段、答案形式统计可用题及库存；无供给时明确缺口和替代路径；模型候选经过验证/适用性检查才进入可靠训练。恢复原子批量提取仍需用户重新授权，不是本审计默认动作。

### D. 个性化、习惯和陪伴

**G16 / P2：长期模型对当前教学的控制仍偏全孩子汇总。**

`child_model.py:355` 的节奏控制由全孩子提示比例、累计卡住反馈等触发，接口无当前知识点/任务参数。已有长期模型并非只存聊天；缺的是情境化使用。

验收：熟练数学和薄弱英语采用不同支持；最近疲劳不永久成为能力标签；每个控制选择能追溯证据、时效、家长覆盖和撤回。

**G17 / P2：策略试用/回滚存在，教法比较与选优不足。**

`strategy_evolution.py:149,895` 有受限策略、历史基线/白名单和版本化回滚；replay 不是把候选教法对同类任务实际比较，单次失败也不能代表长期劣势。

验收：在相近难度、同技能和提示条件下比较独立表现、保持、耗时和负担，设最小证据量及停止条件；不足时不声称获益。两名孩子样本小，不能虚构统计显著性或因果结论。

**G18 / P1：观察少了可能被算成习惯改善。**

`behavior_model/service.py:546,674` 主要比较每日事件计数，习惯实验下降 20% 可标 improving，未按有效观察时长/任务机会归一化，复合成功标准也未被完整检验。

验收：相同事件率但观察时间减半，不能判进步；只有接入真实观察覆盖与任务情境，并验证返回任务、适当求助或独立执行等目标行为后，才支持改善结论。

**G19 / P2：干预是否有效尚未充分影响选择。**

`behavior_model/service.py:470` 统计 helpful_effects，但策略主要依据拒绝比例调整频率。

验收：接受度相同、恢复效果相反时，策略应谨慎选择不同支持或停止无效提醒；不能只因孩子接受就增加频率，也不能由画面预测情绪/人格。

**G20 / P1：活动时间结束不等于现实行动完成。**

`agent_runtime.py:1019,1514` 活动时限/轮次完成可恢复原任务。预算控制应保留，但运动/整理/回到书桌仍需独立确认，不应因为时钟到时就记录有效学习。

验收：分别记录活动结束、孩子反馈、可观察结果和任务恢复；能温和接受拒绝、不使用内疚/排他关系话术，仍鼓励真实家庭互动。防依赖效果属于长期验证，不能只靠提示词保证。

**G21 / P2：板书同步目前主要靠估时。**

`TutorBlackboard.tsx:20` 用文字长度/提示时长累计；`SessionWorkspace.tsx:3429,3586` 重载展开与播放调度不足以代表真实音频位置。

验收：以实际音频段播放进度驱动板书，插话/网络停顿/重启后仍在同段；“退一步、这里再讲讲”定位现有步骤，不提前泄露后续答案或重生成整题。

### E. 家长、运营与发布

**G22 / P1：报告有用度被映射成行动有效反馈。**

`repository.py:2458` 把快照 helpfulness 投影为 executed=1/effectiveness；`reports.py:220` 再用于建议调整。报告有用不等于家长执行，更不等于孩子受益。

验收：报告质量、行动采纳、实际执行、成本/压力、孩子后续结果分别记录；按场景和行动版本调整话术/行为，而非跨场景平均后只改变分钟数。

**G23 / P1：设备、声学、纸面理解的发布证据仍不闭合。**

最新安装版首帧失败；正式库没有可验证的错题完整结果。此前真实页回放、合成语音探针可复用但不替代连续真实输入。

验收：无需先让孩子试错，可用成人自然对话和非家庭样卷先跑摄取→分题→原作答确认→错因验证→入库→讲解→独立复测→次日恢复；之后再验证儿童声学、书写和个体化质量。

**G24 / P1：评测强于“有没有调用”，弱于“有没有正确完成整件事”。**

`model_eval.py:42` 以概念关键词、禁语/泄题正则评估回复；现有语音意图、OCR、硬件性能和真实旅程测试有价值，但尚无足以支持最终目标的统一质量结论。

验收：固定一套完整多轮/跨天旅程和反例，指标覆盖意图到结果、漏话/错误动作、错误掌握声明、同题假迁移、恢复、数据隔离、延迟与费用；测试结果分注入层/真实模型/声学/设备/真实学习，不能混在一起。

**G25 / P2：发布运维及家长实际工作量仍有未验证项。**

已有预算、日志、恢复、投递、审核工作台；未证明最低配置长稳、全故障矩阵、跨机恢复、实际收件送达及正常家庭条件下的审核负担。

验收：一条学习任务能串起音频接收、识别、决策、设备回执、教学、结果和模型版本，供家长/开发者理解故障；正常使用不要求家长逐条审批大量低价值材料。隐私/安全所需确认不能为方便而取消。

## 6. 应当保留与重构什么

### 保留

- SQLite 系统记录、迁移/备份、来源证据、幂等键、双孩子隔离、删除与撤回路径。
- 已存在的能力实现、模型网关、预算及权限边界、设备桥、OCR 质量门、Tutor/错题/计划/报告服务。
- 本地资料与独立构建库资产、审核流程、未批准内容不能证明掌握的规则。
- 已有测试与故障证据，将它们变成重构保护网，不为新架构重写一切。

### 重构重点

不需要另做一个更庞大的功能菜单，也不需要先单独训练通用大模型。应完成两个权威控制面：

1. **学习任务执行控制面**：当前孩子、目标、题目/书页版本、正在等什么、正在说哪段、未完成义务、下一步及取消/恢复状态只有一份权威记录。前端负责展示、声学输入和设备动作，不持有教学执行所有权。
2. **学习证据与教学控制面**：评分资格、提示暴露、题目等价身份、时效/撤回、知识点及成功标准覆盖统一判断；错题本、专项、孩子模型、计划和报告消费同一有效投影。

建议的数据流：

```text
声音 / 页面修订 / 可观察行为 / 时间事件 / 家长反馈
  -> 输入质量、身份与来源确认
  -> 统一任务上下文 + 有效证据投影
  -> 教学与计划决策（云端语义能力 + 本地课程/验证器 + 安全规则）
  -> 受权限、预算、取消和幂等约束的能力执行
  -> 实际回执 / 孩子回答 / 外部副作用核对
  -> 下一决策：继续、追问、等待、转任务、失败恢复、达标结束
  -> 复测义务、孩子模型、长短期计划、家长行动
```

所有主动声音经过同一发言仲裁；所有等待有具体问题/有效期/中断及恢复策略。持续执行不意味着无限调用云端或不断对孩子说话，要有无进展检测、调用预算、安静模式和明确停止条件。

课程图谱是提供教学约束和证据的服务，不是智能体本身。LLM Wiki 可用于可读记忆摘要，不能替代事务型事实、评分和掌握证据。云端更适合自然语义、教学候选、解释及开放评分建议；是否真的执行、数据能否外传、是否学会和如何撤销，不能只由一句模型回复决定。

## 7. 按最终目标重新排序的完整研发门槛

以下是实现顺序，不是删范围的 MVP；前一阶段达标后继续后一阶段，不能把阶段结果写成整产品完成。本轮用户要求先全面审计，故不擅自开始这些重构或发布。

| 顺序 | 工作包 / 负责模块 | 主要缺口 | 离开该阶段的证据 |
|---|---|---|---|
| R1 | 统一可靠学习证据 / 评价、错题、专项、孩子模型 | G06–G10、G18、G22 | 反例测试与跨模块集成证明同一证据得到同一结论；撤回后全链一致降级 |
| R2 | 跨页面持续执行 / Runtime、前端、设备/声音桥 | G01–G05、G20–G21 | 一次表达完成多动作旅程；插话、纠正、临时任务、取消/重启可接续；不依赖点击或页面 |
| R3 | 课程与可用题资产 / 内容、课程、评分供应 | G09、G13–G15 | 两孩子当前课程及长期路线有版本化覆盖账；每个重点能力有真实解释/诊断/练习/迁移/评分资源，缺口有处置 |
| R4 | 长短期计划与策略改善 / 目标、计划、孩子模型、行为 | G11–G12、G16–G19 | 跨周合成旅程中不同基线/失败/时间/负担产生不同可执行方案；真实反馈可修订，无证据不宣称改善 |
| R5 | 陪伴与家长完整闭环 / 活动、报告、教练、家长中心 | G20、G22、F11–F15 | 活动不混同完成，回到学习；日报到周月趋势、投递、家长行动和次日反馈闭合并可纠错 |
| R6 | 全量回归与家庭发布 / 全模块、Windows 运维 | G23–G25、F16–F20 | 非儿童样本先通过整日/跨天/故障矩阵，正式目标环境长稳/恢复，再进行两孩子真实用户与结果验证 |

R1/R2 解决根本控制问题；设备首帧排查可以独立进行，但不能继续用反复改语音关键词掩盖上层缺口。R3 的数据工作不包含未经授权恢复已停止的原子批处理。

### 儿童参与前必须完成的代表性验收

- 自然语言任务集：至少覆盖全部注册能力及未注册但属于日常范围的修订/删除/撤销；每类包含转述、否定、纠正、指代、跨阶段和复合意图，不以匹配预制词为通过。
- 四年级整日：不完整课堂复盘→录多科作业→临时追加/改错→看书/做题→问原因→独立变式→PET 听说读写分配→休息返回→总结→家长建议→次日复测。
- 初三整日：多科作业/学校考试小题→定位真实错题及前置缺口→讲题/板书/过程评分→限时训练→变更可用时间→重排不丢义务→跨天保持。
- 两人隔离：交替使用、半途换孩子、旧设备回执延迟到达、报告/记忆/音色/唤醒偏好恢复，不能串人或错误归因。
- 观察反例：倒置、翻页、手遮、同页修改、看题停顿、短时离座、设备断开；证据不足不判断错误/习惯，恢复后不使用旧帧冒充新观察。
- 教学反例：否认粗心、猜对、照读、提示后正确、同题换 ID、最终答案对但过程错、开放答案同义、来源撤回；不得虚增掌握或进阶。
- 中断矩阵：断网/超时/限流、音频队列拥塞、进程退出、休眠唤醒、设备占用、结果已写入但回执丢失。每例核验恢复、重复副作用、费用和孩子看到/听到的反馈。
- 跨天模拟：可控时钟推进 48 小时/7 天及两周排程，证明代码处理延期、保持、欠练、报告周期和策略回撤；模拟时间通过不等于孩子真实保持率通过。

质量门槛必须在实测前固化口径与用例集，包括任务完成率、错误动作率、需要重说/点击次数、p50/p95 等待、OCR/评分误差、错误掌握声明、日成本及恢复成功率。数据串人、未授权外传、撤销后错误证据继续认证、虚报设备执行成功属于零容忍发布反例；其他数值目标需按代表集和家庭约束设定，不能测完再改门槛。

### 孩子参与后才可验证的层级

连续儿童语音、实际纸面习惯、提示接受度、独立完成变化、延迟/迁移、家庭行动成本及考试变化，需要真实纵向证据。以每个孩子自身基线比较，同时记录题目难度、外部授课、作业量和考试差异，不将同期变化都归功于软件。孩子不是发现上述确定代码缺口的测试人员。

## 8. 替代旧判断与后续交付规则

撤回“F04 只待时长校准、F09 不再有代码缺口、F13 只需调整家庭语气、F20 只差真实卷面”的宽泛结论。现有代码和历史测试仍有效，但不能证明这些域的最终能力已经齐备。

后续每个工作包必须同时交付：完整用户旅程、关键反例、持久化/撤回/恢复、目标运行时证据、剩余数据或质量缺口。采用原实现、调整模块还是替换结构，由是否更可靠地实现最终目标决定，而不是为了遵守早期文档。

本审计覆盖完整功能域和已核实的 25 组高优先级差距，并非对数十万行代码作出“没有其他问题”的保证。它区分确定代码缺口、数据缺口和未验证项；正式进入重构前应将 R1–R6 转成逐条可执行测试与交付账，不再以增加功能名称或通过测试数量作为阶段终点。
