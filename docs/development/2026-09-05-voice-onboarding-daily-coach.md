# 语音初始化与每日攻克计划

## 交付流程

1. 家长完成设备、模型和孩子档案配置后，孩子全语音进入自己的空间。首页昵称只用于选择身份，不代替孩子设定唤醒词。
2. 孩子说出名字、确认识别、实际唤醒、分步练习学习表达和高拍仪求助。练习文本不得生成真实作业、诊断、掌握度或设备动作。
3. 每一步在本机保存后推进；重启恢复，双孩子隔离，支持重听、以后再学、重新教程。隐私停止始终优先。
4. 每日总结来自真实课堂回忆、作业完成状态、题目诊断、复盘与学习过程证据。自述和模型假设必须区别于已验证事实。
5. 薄弱点进入已有计划与复测体系，记录来源、行动、时长、到期与延期理由。讲解和任务勾选不得替代独立作答及延迟检查。

## 验收门槛

- 新用户无需点击功能键完成初始化；已有用户不丢失唤醒词。
- 设置写入失败不宣称成功；并发写入不覆盖另一孩子；重启可继续。
- 教程练习不污染真实学习记录，停止和跳过可恢复。
- 每日总结和复习安排具有持久证据、幂等性、双孩子隔离与失败恢复。
- Windows 实际安装运行验证与两名孩子真实使用/长期结果分别报告，不以自动化测试代替后两层。

## 实现与恢复边界

- 语音教程复用现有拟人智能体入口，不增加孩子必须操作的功能按钮。孩子依次完成命名确认、实际唤醒、课堂/作业表达、拍题求助和结束学习练习；固定教程与真实任务隔离，支持重听、跳过、恢复及重新教程。
- 教程进度和唤醒词分别由 Electron 主进程持久保存，按孩子隔离，串行原子写入。损坏文件不静默覆盖，重复唤醒名字需重新选择，不保存原始录音。
- 本地 `daily-learning-summary` 按北京时间的证据日期汇总，而不是把整场跨午夜学习都算到结束日。自述、观察、讲解和独立作答分开；每日复盘的多个字段不会互相覆盖。
- 会话完成后的总结/复测排程在一个事务中提交，失败保存不含正文的重试检查点。客户端结束请求丢失回包时读取正式会话状态；服务重启可恢复。总结正文按有效来源重建，不复制到云端对话或长期缓存。
- 到期复测进入真实日计划；题目接口绑定孩子、会话、计划项和复测记录。开始后自动读题，语音回答保存真实作答，再结束本次计划项。答错允许结束本次尝试并继续安排后续检查，不要求连续刷到答对；仅说“完成了”不能代替作答。
- 错题来源被排除时撤销其派生的复测和未开始计划，不影响同知识点的其他独立证据。撤回 Tutor 评价不能留下仍被执行的缓存追问。仍需订正的作业形成持久待办并经过次日承接确认。
- 学习结果仍须独立检查、变式迁移和延迟复测。此功能不宣称仅凭日报或一次作答已提高成绩。
