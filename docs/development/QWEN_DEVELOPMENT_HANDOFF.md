## 接管契约

千问可以成为主要代码候选生产者，完整范围保持 W01-W33、F01-F20、
G01-G25、J01-J16。不把任务交接缩减为 MVP，也不把模型自报完成当验收。

1. Codex 从现有脏工作树逐个审核需要提供的文件，固定内容哈希；不复制整个
   工作树、Git 历史、家庭数据库、教材、声音、截图、日志或凭据。
2. 模型请求协调器与离线代码执行器分开。钥匙串凭据只进入协调器，绝不进入
   候选进程的环境、参数或日志。模型不得提供需要直接执行的 shell 命令。
3. 每项冻结验收条件、允许修改文件、已审核输入哈希和可信测试命令。
   模型输出只落隔离候选目录，不直接覆盖工作树。
4. 设定调用/输出/运行时间/重试上限，失败保留检查点，不无限重试或静默收费
   回退。Token Plan 不可用才考虑已授权官方 DeepSeek，并明确记录实际供应方。
5. Codex 审查代码和副作用后，在关闭网络的执行器内运行批准的检查。
   不给生成的测试数据库、设备或部署权限；测试通过仍需独立反例审查。
6. 合并前重新核对原文件哈希；主工作区变化则停止应用该候选，不覆盖并发工作。
   每个候选独立记录 approved/rejected/needs_revision，不自动 commit/cherry-pick。
7. Codex 额度耗尽时可保留候选与检查点待审，但不得宣称有人继续验收。
