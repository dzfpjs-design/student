## 1. 决策摘要

### 1.1 推荐方案

采用 **本地权威状态 + 云端分析候选 + 本地有界策略实验** 的混合架构：

1. 本地保存不可覆盖的学习与行为证据、版本化孩子状态、计划、干预、结果和修订历史。
2. 云端模型负责自然语言理解、错因与非执行原因假设、教学方案、计划候选和周期复盘，不直接写入掌握度、习惯结论或长期事实。
3. 本地确定性服务检查证据资格、孩子隔离、冲突、有效期、家庭约束和策略权限，再决定是否采用云端候选。
4. 教学方法和行为干预通过同一孩子的有界 N-of-1 实验比较；一次只改变一个主要变量，证据不足不下因果结论。
5. 优化目标是独立完成、迁移、延迟保持、主动习惯和家长提醒减少，不是使用时长、顺从度或“孩子说懂了”。

### 1.2 不推荐的替代方案

| 方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| 云端维护完整孩子画像 | 开发快、语义能力强 | 不可重放，结论易漂移，成本与隐私扩大，离线失效 | 不采用 |
| 完全本地规则与小模型 | 可控、隐私强、离线稳定 | 复杂语言、错因、计划解释和开放回答能力不足 | 仅作降级路径 |
| 端到端黑箱“自我进化” | 表面自动化程度高 | 无法证明为何改变策略，难以撤销，容易把相关性当因果 | 禁止进入生产决策 |

### 1.3 产品原则

- 孩子模型描述“在特定情境下，根据哪些证据，当前最可能是什么”，不输出人格或医学标签。
- 当日疲劳、挫败和接受程度是短期假设，默认过期，不能沉淀成长期性格。
- 一次答对、接受提示后答对、重复同题答对和模型评分，均不能单独证明稳定掌握。
- 提醒的长期目标是逐步退出；如果系统越用提醒越多，视为策略失败信号。
- 两名孩子的证据、状态、策略、计划、实验和报告严格隔离。

## 2. 当前状态与差距

### 2.1 已观察到的实现

| 能力 | 当前实现证据 | 当前判断 |
|---|---|---|
| 孩子状态快照 | `child_model_snapshot` 已保存模型版本、证据指纹、水位和当前快照 | 有版本化基础，但运行时读取可现场重算且不保证每次决策引用已持久快照 |
| 知识状态 | 已有 `learning_evidence`、`mastery_state`、有效证据投影及独立/迁移/保持门禁 | 局部闭环较强，尚未成为每日计划和所有教学入口的统一决策输入 |
| 行为状态 | 已有日特征、个人基线、趋势、观察覆盖和干预反馈 | 有统计投影，真实孩子跨周校准和误提醒率未验证 |
| 习惯训练 | 已有目标确认、机会分母、`habit_experiment`、减提醒消费者 | 尚缺完整自动状态机、稳定的提示衰减和跨场景保持闭环 |
| 教学策略实验 | 已有 `strategy_experiment`、影子/启用/回滚及有限教学控制 | 主要集中于讲解节奏，结果归因和跨策略比较范围不足 |
| Agent Runtime | 已有目标、计划、步骤、能力回执、结果与后续承诺 | 不是所有回合都强制消费同一版本孩子状态和策略决策记录 |
| 家长报告 | 已有日报、周报、月报与建议反馈 | 报告能展示状态，但反馈对次日计划和长期策略的闭环仍不完整 |

### 2.2 根本差距

当前最大的架构缺口不是“缺少更多模型”，而是以下六件事尚未形成一条权威链：

1. **统一状态**：知识、学习过程、习惯、当日状态和交互偏好没有统一的版本化决策快照。
2. **统一消费**：计划器、Tutor、陪伴、主动提醒和家长建议没有强制引用同一快照版本。
3. **假设协议**：云端输出缺少统一的“支持证据、反证、置信度、有效期、核实动作”契约。
4. **结果归因**：一次干预之后发生的恢复、完成、独立作答和延迟保持，尚不能稳定归因到具体策略版本。
5. **提示退出**：习惯出现后如何逐级减少提示、验证迁移、复发后恢复，没有完整自动执行状态机。
6. **真实校准**：缺少两名孩子各自的基线、误提醒率、教学策略效果和多周结果证据。

因此当前状态仍是 `partial`：代码组件较多，局部集成与持久化已有证据，但 `target_runtime`、`real_user`、`outcome` 均未完成。

## 3. 目标孩子模型

### 3.1 五个状态域

每个孩子维护五个相互关联但不可互相冒充的状态域：

| 状态域 | 核心字段 | 合格证据 | 典型用途 |
|---|---|---|---|
| 知识与能力 | 掌握、记忆稳定性、可提取性、独立性、迁移、不确定度 | 版本化作答、提示暴露、评分、变式、延迟复测 | 补弱、复习、教学深度 |
| 学习过程能力 | 审题、计算、阅读、表达、检查、反思、迁移步骤 | 草稿、分步回答、作品修订、过程问答 | 讲解和练习设计 |
| 学习习惯 | 启动、持续、恢复、切换、求助、检查、复盘、独立 | 有效机会、可观察动作、任务回执、孩子/家长纠正 | 选择单一习惯目标和提示方式 |
| 当日状态 | 精力、疲劳、挫败、负荷、接受程度 | 当日自述、任务表现、短期观察 | 调整当天节奏；默认短期失效 |
| 交互与教学偏好 | 讲解长度、提示梯度、语气、节奏、休息方式 | 多次选择、纠正、策略实验结果 | 控制 Agent 表达和 Tutor 策略 |

### 3.2 统一 `ChildStateSnapshot v6` 契约

复用现有 `child_model_snapshot`，升级 payload，不新建旁路画像库。每份快照必须包含：

```text
identity: child_id, grade, curriculum_region
snapshot: snapshot_id, model_version, evidence_fingerprint, created_at
knowledge: node states, due reviews, weak clusters, uncertainty
learning_process: skill states by subject/task/context
habits: baselines, trends, active goal, stage, opportunity counts
daily_state: hypotheses, confidence, expires_at, verification_action
interaction: verified preferences, active corrections, experiment controls
goals: long-term milestones, current constraints, feasibility risks
plan_context: unfinished obligations, due checks, load and time budget
open_hypotheses: evidence_for, evidence_against, next_verification
active_strategy: version, scope, experiment_id, stop/rollback rules
provenance: source watermarks, algorithm versions, cloud analysis versions
```

快照必须满足：

- 任一字段能下钻到证据或明确标注 `unknown`。
- 临时状态有 `expires_at`；证据撤回后可以重放并产生新快照。
- 快照只追加版本，当前指针可切换，历史快照不可覆盖。
- Runtime 的每个计划和重要行动保存 `snapshot_id`、`strategy_version` 和 `decision_record_id`。
- 现场读模型用于低延迟时，必须保存证据指纹；执行前重验，不能把旧计算结果写入新状态。

## 4. 目标闭环架构

```text
麦克风/高拍仪/摄像头/产品操作/孩子与家长反馈
                         ↓
                 Evidence Ledger
                         ↓
        知识投影 / 行为特征 / 任务结果 / 当日状态
                         ↓
             Child State Snapshot v6
                         ↓
       ┌─────────────────┴─────────────────┐
       ↓                                   ↓
Cloud Child Analyst                 本地规则与约束引擎
假设、解释、候选策略                证据资格、预算、权限、回滚
       └─────────────────┬─────────────────┘
                         ↓
      Strategy Experiment + Decision Record
                         ↓
      长期路线 → 周计划 → 日计划 → 当前下一动作
                         ↓
      Agent Runtime：语音、Tutor、设备、提醒、陪伴
                         ↓
        Outcome Evaluator：独立/迁移/保持/习惯结果
                         └──────────→ 新证据与新快照
```

### 4.1 本地权威服务

1. `EvidenceLedgerService`：统一事件、幂等、撤回、修订、重放。
2. `ChildStateService`：按同一事务视图构建和持久化快照，提供紧凑运行时投影。
3. `LearningOutcomeService`：区分提示后正确、独立、迁移、延迟保持。
4. `BehaviorStateService`：按任务与情境计算机会、基线、趋势和不确定度。
5. `StrategyExperimentService`：管理候选、影子、启用、停止、回滚和比较。
6. `PlanningPolicyService`：将长期目标、到期复测、作业、负荷和习惯训练编译成计划。
7. `DecisionRecordService`：记录候选、约束、采用原因、被否决原因和预期结果。
8. `OutcomeAttributionService`：把行动结果绑定到快照、策略、干预和任务版本。

### 4.2 云端分析角色

云端模型仅处理最小必要的派生文本与结构化状态，承担：

- 理解孩子自由表达、课堂复盘和计划不执行原因。
- 结合多道题提出错因、前置缺口和核实问题。
- 生成分层教学、练习和适龄表达候选。
- 生成日计划解释、周策略比较和家长沟通候选。
- 发现状态中的矛盾、过期假设和待验证问题。

云端返回统一 `AnalysisCandidate`：

```text
candidate_id, child_id, task_type, scope
claims[]: claim, evidence_refs, counterevidence_refs
confidence, uncertainty_reasons, valid_until
verification_actions[], proposed_actions[]
expected_outcomes[], stop_conditions[], rollback_action
model_provider, model_name, prompt_version, response_version
```

禁止云端：

- 直接修改掌握概率、习惯状态、长期记忆、计划完成状态或家庭规则。
- 把模型常识当成孩子事实。
- 接收连续家庭视频、原始环境音或无关的完整历史。
- 以自己的评分作为唯一能力证据。

### 4.3 降级原则

- 云端不可用：继续执行已有计划、到期复测和本地习惯目标；复杂解释转为澄清或稍后处理。
- 摄像头不可用：行为结论降为 `unknown`，不能用缺失观察推断不专注。
- 高拍仪不可用：允许口述或稍后补拍；不能伪造题目内容。
- 状态过期或冲突：Runtime 先重新构建快照，再执行动作。

## 5. 两条核心结果闭环

### 5.1 学习成绩提升闭环

状态机：

```text
发现薄弱候选
  → 用原题/过程/口述核实
  → 映射知识与过程能力
  → 选择教学策略
  → 分层提示，不直接泄露答案
  → 孩子独立复述或完成新题
  → 近迁移
  → 表征变化或远迁移
  → 48 小时/7 天延迟保持
  → 更新状态或重新补救
```

退出门槛必须同时关注：

- 是否独立完成，而非只看正确。
- 是否在不同题或情境迁移。
- 是否经过真实间隔仍能提取。
- 是否降低提示需求。
- 是否保留可解释的错因修订路径。

### 5.2 学习习惯形成闭环

状态机：

```text
observe（观察 5-10 个可靠机会）
  → propose（系统提出一个可执行目标）
  → negotiate（用适龄语言说明目标，孩子可表达愿意、修改、拒绝或不理解）
  → baseline（建立同情境基线）
  → cue（环境提示）
  → practice（练习目标行为）
  → reinforce（具体强化行为与策略）
  → fade（逐级减少提示）
  → transfer（跨科目/时间/任务验证）
  → maintain（低频检查）
  → recover（复发时恢复较低强度阶段）
```

一次只训练一个主要习惯。每个实验必须保存：

- 目标行为与反例，适用情境和有效机会定义。
- 基线窗口、最低样本量和观察缺失规则。
- 提示层级 `L3 明确提醒 → L2 简短线索 → L1 环境线索 → L0 无提示`。
- 成功指标、负担指标、误提醒率、停止与回滚条件。
- 孩子的接受、拒绝、纠正和希望安静的反馈。

这里的孩子反馈不是让孩子判断“系统分析得是否科学”，也不是把实验批准责任交给孩子。决策权分为三层：

1. **系统责任**：判断证据是否足够、目标是否具体、策略是否低风险，并为结论和停止条件负责。
2. **家长授权**：在初始化或家长中心一次性设定允许自动开展的低风险习惯范围、提醒时段、强度和禁用项；超出范围或持续效果不佳时再请求家长决策，不要求逐次审批。
3. **孩子参与**：孩子只需理解“这次准备练什么”，可以说愿意、换一种、别提醒、没听懂或不知道。拒绝和不适必须被尊重；孩子沉默、无法判断或随口答应都不能成为习惯结论或升级干预的证据。

若孩子不能有效表达选择，系统只能继续观察，或在家长预授权范围内尝试可立即停止的低强度环境线索；不得提高提醒强度、形成固定标签或声称孩子已经认可目标。`5-10` 是首版证据门槛范围，不是机械次数：至少需要 5 个质量合格且同情境可比较的机会；观察噪声大、情境不同或存在反证时应继续收集，不能为达到次数而启动训练。

首批可训练目标按优先级选择：按约定时间开始、遇到困难先独立尝试、完成后主动检查、休息后按时返回、结束时做一句复盘。系统只能基于实际机会提出目标，不能预设孩子有某个坏习惯。

## 6. 每日、每周和每月运行节奏

### 6.1 每日

1. 开始前：读取最新快照，采集当日约束和自述，确认设备与未完成义务。
2. 计划：编译作业、复测、补弱、长期目标和一个习惯练习机会，给出可理解理由。
3. 学习中：观察任务与页面，微干预，按提示梯度教学，记录真实回执。
4. 每个任务后：核对完成标准，生成独立检查或后续复测，不用“讲完”结算掌握。
5. 当日结束：本地固化事实和结果；云端生成候选分析；本地校验后形成次日待验证项。

### 6.2 每周

- 比较知识迁移与保持、计划偏差、习惯机会和提示负担。
- 评估当前策略实验：继续、减弱、停止、回滚或换一个变量。
- 检查长期目标路径是否可达，重新分配下周负荷。
- 生成家长可执行话术、当天行动、时长、停止条件和错误示例。

### 6.3 每月

- 复核教材、考试、PET/竞赛目标与阶段里程碑。
- 区分真实改善、数据不足和短期波动。
- 清理过期假设，归档已证伪策略，保留完整修订历史。
- 评估是否减少 Agent 提示和家长催促，防止形成依赖。

## 7. 实施工作包与依赖

以下是依赖顺序，不是 MVP，也不删除任何完整范围。

### P0：冻结契约与基线

交付：

- 对现有事件、快照、策略、计划和结果表做兼容映射。
- 固化 `ChildStateSnapshot v6`、`AnalysisCandidate v1`、`DecisionRecord v1`、`OutcomeAttribution v1`。
- 建立两名合成孩子的 30 天回放数据与反例集。
- 给旧数据迁移、回滚和重放建立固定版本门禁。

完成门槛：删除派生状态后重放一致；两个孩子零串档；旧消费者有明确迁移表。

### P1：统一孩子状态读模型

交付：

- 在现有 `child_model_snapshot` 上实现五域快照和字段级证据索引。
- Runtime、计划、Tutor、主动提醒和报告统一通过一个紧凑状态接口读取。
- 每次决策写入快照与证据指纹，执行前检查过期和冲突。

完成门槛：同一时刻五个消费者引用同一快照；撤证、纠正和重启后状态一致。

### P2：云端分析候选与夜间复盘

交付：

- 实现结构化云端请求/响应、最小字段白名单、超时、退避和本地降级。
- 将课堂复盘、错题、计划执行、行为机会和孩子反馈汇总为日分析候选。
- 候选经过证据存在、冲突、有效期和禁用标签校验后才进入开放假设。

完成门槛：模型胡编证据、跨孩引用、过期建议和格式错误均不能污染孩子模型。

### P3：计划编译与 Runtime 强制消费

交付：

- 长期路线、周目标、日计划和当前下一动作共享同一约束与优先级。

## 9. 六层验收矩阵

每个 P1-P7 工作包都必须分别记录：

| 层级 | 通过标准 |
|---|---|
| `code` | 正式实现存在，无演示回退；契约、迁移、错误路径和自动测试通过 |
| `integration` | 设备/输入、Runtime、模型、状态、计划、数据库和报告真实串联 |
| `durability` | 刷新、应用重启、服务重启、断网、重复提交和异常恢复后正确 |
| `target_runtime` | 固定版本在目标 Windows 和真实设备通过 |
| `real_user` | 两名孩子可全语音完成流程，家长可理解和反馈，不需开发者解释 |
| `outcome` | 出现可追溯的独立、迁移、保持、习惯或家长行动改善，并有反证与不确定性 |

只有六层全通过才标记 `complete`。当前本方案对应的完整能力仍为 `partial`。

## 10. 风险、停止条件与回滚

| 风险 | 处理 |
|---|---|
| 把相关性当策略效果 | 单变量有界实验、最低样本、对照基线、明确“不确定” |
| 观察错误造成频繁提醒 | 覆盖门槛、个人基线、冷却预算、孩子纠正、自动降为影子 |
| 云端模型制造孩子事实 | 证据引用校验、候选状态、有效期、禁止直接写权威表 |
| 过度依赖 Agent | 以提示衰减、无提示成功和现实活动转化为目标 |
| 计划负担过重 | 睡眠/家庭硬约束、负荷预算、孩子协商、自动减载 |
| 数据越积越乱 | 事件不可变、派生可重建、版本水位、修订与撤销链 |
| 旧模块绕过新契约 | 消费者清单、契约测试、旧接口监控、逐项迁移后封禁旁路 |

## 11. Gate 提案

本方案涉及孩子模型、云端职责、计划策略和干预状态机，属于重要产品与架构决策。建议批准以下基线：

> 采用“本地权威孩子模型 + 云端分析候选 + 本地有界策略实验”；按 P0 到 P8 顺序实施；系统在达到可靠证据门槛后才可提出一个习惯目标，在家长预授权范围内开展可随时停止的低风险尝试；孩子拥有适龄知情、表达偏好、纠正和拒绝权，但不承担科学判断或批准责任；任何未验证推断不得直接改变掌握、习惯或长期计划。

批准后先执行 P0-P1，冻结契约和统一孩子状态；若实施中需要改变云端数据边界、权威事实来源、家长授权范围、孩子异议权或策略自动启用规则，必须重新回到产品/架构 Gate。
