# PET 原音频教学实现约束

2026-09-11。这是待实现的工作规格，不是功能完成证据。所属 W05/W06/W11/W22；
20 域仍 partial。四年级开放题和专项供给分别由 Pascal/Sagan 的独立 COPY 继续。

## 已确认的现状

- `pet_media_evidence` 已绑定原 prompt/item_version/voice_input，保留音频哈希并校验来源。
- `pet_speaking_origin.original_answer_voice` 区分原答案与后续确认/控制发言，不能选择最近一段音频代替。
- `learning_outcome_evaluator.prepare_local_evaluation` 将 PET 参考评分保存为本地待复核。
- `_current_oral_feedback` 重新验证原题、回答、目标和执行状态，然后投影本地反馈。
- `oral_teaching.project_oral_teaching` 没有有效原音频复核时只给任务自查，不自动评价声学能力。
- `pet_speaking_acoustics` 目前只有录音及 VAD 可用性，明确没有声学评分器。
- `pet_audio_rubric` 的可靠入口是逐段原音频人工复核；后续失败/撤销会否定旧成功。
- `rubric_calibration.freeze` 目前仅支持文字模态；简单增加 original_audio 枚举不能构成音频校准。
- 普通 `ModelRequest` 只接受文本，禁止为了方便将音频塞进文本字段或日志。

## 官方传输合同

2026-09-11 阅读 [Qwen-Omni 官方文档](https://help.aliyun.com/zh/model-studio/qwen-omni)：
原音频通过 `input_audio` 传入，支持本地 Base64；HTTP 调用必须使用流式响应。
本项目只请求文本反馈，不让供应商直接播报未验证的自由回复。编码大小、输入时长、
输出字节数及总耗时必须有界。文档支持输入不代表本账号可调用，也不证明 PET 评分质量。
本次没有发送家庭数据、使用密钥或进行付费探针。

## 完整纵向链路

1. 原答案已保存后，按精确 prompt/item_version/attempt/evidence/media 产生本机评价工作项。
   再次提交、刷新或重启沿用原工作项，不重新选择最近声音，不自动重复收费请求。
2. 每次真正发出音频前重新检查当前孩子、活动会话、原目标、原答案、用途授权、
   `cloud_audio_allowed`、删除状态和预算。ASR 已调用或文本许可不构成音频评价许可。
   本地媒体投影的 `cloud_transmission_allowed=false` 不能直接改成 true 或转发。
   需要新建明确的最小用途投影；只能包含当前已授权的原回答音频和必要题目要求。
3. 新音频 Gateway 负责有界 SSE 解码、同源凭据、配置校验、每次实际 POST 的授权回调、
   总截止时间和错误分类。不得复用 `CloudAsrGateway` 的非流式协议或静默降级为文字评分。
4. 模型返回类型化反馈：每条观察包含原音频内的时间区间、维度、具体观察、
   一项可做的练习建议，以及不确定性。未观察到的维度必须未知；不得用字数、音量、
   口音差异或转写标点推断发音/流利度。模型不能自行授予播报/记忆/评分/操作权限。
5. 保存前再校验同一原录音/题目/授权。先持久化结果，再由现有 Runtime 在当前目标下
   交付反馈；断流、未知结果或原对象变化不自动重发、不播报半截评价。
6. 未校准结果属于形成性练习建议，不进入可靠掌握度，不宣称考试分数。关联原回答
   的长期记录可记录“建议及孩子是否实践”，不能把建议写成孩子确定的缺陷。
7. 孩子愿意再试时调用现有口语 followup：创建新 prompt/capture，保留原反馈谱系。
   改善要比较两次真实原音频，新的独立任务不能被原题重复伪装。
8. 可靠声学评分另接校准链：原音频来源、盲标样本、模型/提示/参数/音频预处理版本、
   各维度误差和拒判阈值、实际端点返回身份均匹配后才能给可靠评分。
   校准过期、源删除、后续人工否定、模型变化均重新撤销资格和下游计划证据。

## 数据与失败恢复

- 工作项状态区分 queued、running、response_saved、delivered、failed、unknown、invalidated。
- 幂等键绑定孩子和原答案，禁止凭同 key 更换音频；晚到结果不能归到另一孩子/新题。
- 不保存 Base64 或音频副本；仅引用现有加密媒体。诊断日志只有哈希、状态、版本和用量。
- 原音频上传不允许 URL 重定向，也不允许用户提供任意本机路径或远程音频 URL。
- 删除/撤销/备份恢复必须覆盖工作项与引用；恢复前的许可不能自动授权恢复后的发送。
- 成功收到模型文本不等于结果已播报，已播报不等于孩子练过，练过不等于掌握。

## 验收门槛与实现顺序

先实现原回答工作项和最小用途投影，连通 Gateway、持久化、Runtime 反馈及新录音复练；
不能以一个独立可调用的音频脚本或接口作为结束点。随后实现原音频校准和计划消费者。

必验场景：

- 真实本机 HTTP/SSE：分块、半个 UTF-8、未知 JSON 字段、输出超限、超时、429、断流。
- 原回答与确认发言同时存在时只能评价前者；切孩、换题、撤回来源、媒体改字节均拒绝。
- 等待配置、排队、实际发送前、返回前及保存前撤销许可都不能取得新的发送/保存权限。
- 真实临时 SQLite 和加密原音频：刷新、整应用/后台重启，保存和播报状态不丢失。
- 正常反馈能够引导新录音、保留练习谱系并进入家长每日总结；未知/未校准不改变掌握度。
- 模型实际质量与耗费使用已允许的非家庭语音样本验证，不能拿 MockTransport 证明智能程度。
- Windows 声学链和两个孩子的真实表现单独验收；不把合成音或成人读稿冒充儿童证据。

当前边界：以上新增音频工作项/Gateway/自动反馈/声学校准尚未实现或合入，
现有人工原音频复核继续可用。不得将本规格计为 W22 完成。
