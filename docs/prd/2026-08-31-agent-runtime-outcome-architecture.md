# 拟人智能体运行时与能力提升闭环设计

日期：2026-08-31  
状态：实施基线  
替代范围：以意图标签和页面分支为核心的孩子端编排方式

## 1. 最终产品定义

孩子面对的不是一组功能，也不是一个能调用若干按钮的语音助手。孩子只面对一个持续存在的学习伙伴。它负责理解孩子此刻想完成什么，结合长期目标、当前任务、知识状态、行为状态和设备状态，选择并执行适当能力，并继续跟进，直到产生可验证的学习或成长结果。

孩子端遵循以下公式：

```text
拟人智能体 = 唯一交互入口 + 目标管理器 + 能力编排器 + 长期关系载体
```

系统的完成条件不是“生成了回复”或“调用了工具”，而是以下四类结果之一：

1. 学习结果：形成了独立作答、复述、订正、迁移或延迟复测证据。
2. 执行结果：计划、任务、休息、设备或资料状态发生了已确认的改变。
3. 习惯结果：孩子在具体情境中完成一次可观察、可复盘的行为练习。
4. 陪伴结果：共同活动自然结束，并促进情绪恢复、现实行动或学习返回。

## 2. 当前架构的根因

当前实现以 `AgentOrchestrator._cloud_intent_to_local_action()` 和 `SessionWorkspace.submit()` 中的大量条件分支为主干。它存在五个结构性问题：

1. 模型只选择意图标签，不负责形成面向结果的计划。
2. 能力散落在页面、API 和事件监听器中，没有统一能力目录与运行契约。
3. 前端掌握业务执行权，智能体无法知道工具是否真正完成以及产生了什么证据。
4. 对话历史只有短窗口，没有持续目标、未完成承诺和教学阶段。
5. 讲解、计划、错题、行为和陪伴分别运行，不能围绕同一个孩子目标协作。

因此，继续增加意图、关键词或页面动作只会提高局部命中率，不会使智能体更有判断力，也不会提高孩子的真实能力。

## 3. 目标架构

```text
麦克风 / 摄像头 / 高拍仪 / 系统事件
                 ↓
          Perception Gateway
                 ↓
     Context Assembler + Memory Retrieval
                 ↓
     Objective Manager + Agent Planner
                 ↓
          Capability Registry
                 ↓
     Durable Executor / Client Device Bridge
                 ↓
       Evidence Ledger + State Models
                 ↓
       Outcome Evaluator / Next Decision
                 ↓
        Voice Response + Visual Projection
```

### 3.1 Perception Gateway

统一接收语音最终文本、本地视觉事件、高拍仪页面变化、计时器、计划到期和模型/设备故障。所有输入先成为带来源、置信度和时间的事件，不能直接改写掌握度或行为结论。

### 3.2 Context Assembler

每次决策只组装当前任务所需的最小上下文：

- 当前孩子、年级、地区、家庭规则和长期目标。
- 当前会话阶段、当前任务、剩余时间和未完成承诺。
- 当前活动目标及其阶段、成功标准和已经获得的证据。
- 相关原子知识节点、掌握/记忆/独立/迁移状态及不确定度。
- 当前行为状态、近期个人基线和提醒预算。
- 可用设备、模型、知识来源及降级状态。
- 最近对话、被孩子纠正的内容和当前关系记忆。

上下文必须保存清单和版本，但不复制原始影像，也不把全量历史发送给云模型。

### 3.3 Objective Manager

每个持续活动都必须有权威目标，而不是依赖最近一句话猜测：

| 目标类型 | 示例 | 完成条件 |
|---|---|---|
| `learning` | 理解正弦与余弦 | 独立解释区别并完成一题近迁移检查 |
| `execution` | 完成数学作业第3页 | 完成证据和核对状态已保存 |
| `habit` | 练习卡住后先标记条件 | 连续三次任务中完成约定动作 |
| `companion` | 休息时共同讲故事 | 在约定时长内自然结束并返回现实活动 |
| `execution` | 整理今天作业 | 清单经孩子确认且可用于计划 |

一个孩子同时只能有一个前台目标，可以保留多个暂停目标。目标必须支持继续、暂停、替换、完成、失败和取消，应用重启后继续。

### 3.4 Agent Planner

Planner不输出意图标签，而输出下一段可执行计划：

```json
{
  "objective": {
    "mode": "new|continue|pause|complete|cancel|none",
    "type": "learning|execution|habit|companion",
    "summary": "孩子正在努力达成的结果",
    "success_criteria": ["可验证条件"]
  },
  "next_step": {
    "capability": "learning.diagnose",
    "arguments": {},
    "reason": "为什么此刻调用",
    "expected_evidence": ["independent_response"]
  },
  "requires_child_reply": true,
  "spoken_transition": "执行前需要对孩子说的话"
}
```

Planner可以提出计划，但不能直接写入掌握度、行为状态、家长结论或长期记忆。所有权威更新必须来自能力执行结果和证据规则。

### 3.5 Capability Registry

所有能力必须注册，不能继续隐藏在页面条件分支中。每项能力包含：

- 稳定名称与版本。
- 适用目标类型和前置条件。
- 输入、输出和错误结构。
- 执行位置：`server`、`local_model` 或 `client_device_bridge`。
- 风险等级、确认要求、是否可撤销。
- 幂等方式、超时、重试和未知结果恢复策略。
- 会产生的证据类型及是否允许更新派生状态。
- 孩子可理解的进行中、成功和失败表达。

首批能力域：

```text
session.*       报到、复盘、结束和恢复
planning.*      计划生成、解释、调整和执行
learning.*      诊断、讲解、提示、检查、变式和复测
mistake.*       采集、确认、错因、补救、迁移和归档
document.*      页面监控、OCR、题目定位和作答变化
behavior.*      状态读取、提醒决策、反馈和习惯实验
companion.*     聊天、故事、游戏、运动和自然结束
memory.*        关系记忆草案、纠正和检索
device.*        摄像头、高拍仪、麦克风和隐私控制
parent.*        待家长事项和报告证据
```

### 3.6 Durable Executor

服务端能力由后端直接执行。必须访问浏览器媒体或呈现交互内容的能力通过一个通用 `client_device_bridge` 发出命令，前端只负责执行并回报结果，不再理解学习业务。

每个步骤保存 `planned -> running -> waiting_child|completed|failed|unknown`。执行未知时不自动重复收费或重复写入；应用重启后可恢复或询问孩子。

### 3.7 Outcome Evaluator

每个目标有独立结果评估器。以学习目标为例：

```text
提出诊断问题
  → 保存独立作答
  → 定位知识节点和前置缺口
  → 选择讲解/提示/示例
  → 让孩子复述或完成近迁移题
  → 根据提示依赖写入学习证据
  → 更新知识状态
  → 安排延迟复测
  → 复测通过后才完成目标
```

“听懂了”“讲解完成”或模型认为正确都不能单独证明掌握。智能体必须区分当场理解、独立完成、迁移和延迟保持。

纸面题的评分编排必须区分“题干/实际作答事实”和“对错权威”。高置信视觉事实可自动进入评分队列，低置信或冲突时才请孩子澄清自己写了什么。对错权威仅来自老师批改、版本化标准答案或智能体出题时冻结的评分规则。评分可异步完成；合格决定到达后由本地 Runtime 自动且幂等地创建错题或独立复测，不依赖孩子再说“继续”。

## 4. 孩子端界面边界

孩子模式只保留一个交互面：

- 拟人智能体形象、听/想/说/执行/等待状态。
- 实时字幕和可打断语音。
- 当前目标、当前一步、成功标准和进度的适龄呈现。
- 智能体主动调出的题目、教材页、计划或活动画面。
- 明确的麦克风、摄像头和高拍仪状态。

页面导航、按钮和模块不再是孩子完成任务的方式。家长模式、设备修复和紧急隐私控制可以保留触控。

## 5. 数据模型

新增对象必须与现有证据账本和状态模型连接：

### `agent_objective`

保存前台/暂停目标、目标类型、摘要、成功标准、当前阶段、相关知识节点和生命周期。

### `agent_plan`

保存一次决策使用的上下文清单、候选能力、选中步骤、理由、Planner版本和约束结果。

### `agent_step`

保存能力名称、参数摘要、执行位置、状态、幂等键、结果、错误和证据引用。

### `agent_commitment`

保存智能体向孩子承诺的提醒、复测、后续检查和自然结束时间，避免“说过就忘”。

### `agent_outcome`

保存目标结果、结果层级、证据引用、置信度和下一动作。学习目标的结果层级只允许 `exposed`、`understood_now`、`independent`、`transferred`、`retained`。

## 6. 决策优先级

每轮决策按以下顺序处理：

1. 安全、隐私和立即停止。
2. 孩子对当前理解、身份或事实的纠正。
3. 当前前台目标的下一步和未完成承诺。
4. 到期作业、复测和家庭硬约束。
5. 当前可获得的最高学习价值。
6. 行为提醒预算与情绪负担。
7. 陪伴、探索和自由聊天。

智能体不得为了维持对话而阻止孩子离开，不得为了完成计划忽视明显疲劳，也不得为了“鼓励”把未经验证的理解记为掌握。

## 7. 实施迁移

### 阶段一：建立新主干

- 引入统一上下文、目标、能力注册、计划和步骤持久化。
- 新建通用 Agent Runtime API。
- 旧 `intent -> action` 仅作为未迁移能力的兼容适配器，禁止新增分支。
- 前端增加通用设备桥和视觉投影协议。

### 阶段二：完成学习纵向闭环

- 先迁移“提出学习问题”到诊断、讲解、检查、变式、证据和复测。
- 用真实初三数学和四年级英语/数学任务验收。
- 验收后删除对应旧家教分支。

### 阶段三：迁移每日流程与错题

- 计划、任务和错题能力注册并后端执行。
- 页面只接收智能体投影，不再承担业务编排。

### 阶段四：迁移行为、陪伴与主动触发

- 行为状态和干预效果进入上下文。
- 陪伴活动使用目标、计时、边界和自然结束能力。
- 承诺调度器负责提醒、复测和家长待办。

## 8. 验收门槛

只有以下条件同时满足，才能称拟人智能体完成：

1. 孩子不点击功能入口即可完成整日流程。
2. 新增一种能力只需注册能力，不需要修改语音分类器和页面总分支。
3. 智能体可说明当前目标、为什么做这一步、成功标准和下一步。
4. 应用重启后目标、计划、等待孩子回答的步骤和承诺全部恢复。
5. 学习问题至少形成诊断、干预、独立检查和延迟复测证据，不能只留下对话。
6. 前端工具执行失败、模型超时和未知结果均可恢复，不重复写入或收费。
7. 每个掌握变化都能下钻到题目、作答、提示依赖和复测证据。
8. 连续一周真实使用后，能展示知识、独立性或习惯的可验证变化，而不是只展示使用时长。

## 9. 立即停止的旧做法

- 不再为每个新说法增加关键词或单独意图。
- 不再在 `SessionWorkspace` 增加新的业务 `if/else`。
- 不再让模型生成的讲解自动等价于学习完成。
- 不再让页面是否跳转作为能力是否完成的主要证据。
- 不再把聊天历史当作长期目标和长期记忆。
- 不再把“工具已调用”写成“孩子已经获得能力”。
