# 课程知识内化与扩展PRD

更新日期：2026-08-27

## 1. 目标与边界

本模块把课程标准、教材结构、教学视频、课程转录、学校资料和原创诊断题转化为App可执行的学习能力。系统不仅回答“有哪些课程”，还应回答“孩子需要掌握什么、前置能力是什么、常见错误是什么、用什么证据判断掌握、忘记后何时复测、哪种讲解适合当前孩子”。

课程视频与转录属于来源证据层，不直接等同于原子知识点、标准答案或孩子掌握状态。任何由规则或模型抽取的知识对象必须保留来源、成熟度和冲突状态；未经验证的对象只能用于低置信候选和讲解参考，不能直接提高掌握度。

## 2. 当前语料审计

苏e优课源库包含3832个课程条目，3788份转录和3788个本地视频，覆盖小学四至六年级、初中一至三年级。源数据库的`volumn_title`存在大量统一标记为“下册”的异常，但`unit_path`第一层可可靠区分上册和下册；App从章节路径重建学期，不采用冲突的册次字段。

结构化处理后形成3728个课程主题，覆盖6个年级、63个年级-学科组合和123个年级-学科-学期组合。四、五年级各有10门课程且均含上下册；六年级仅有8门；初一综合实践活动只有下册；初二劳动科技和综合实践活动只有单学期；初三只有化学、历史、数学、物理、美术、英语、语文、道德与法治8门课程。该结果证明语料具有较强基础覆盖，但尚不能证明符合全部国家课程要求，也不能证明每个学期的全部基础知识点没有遗漏。

当前3728个主题的成熟度均为`source_structured`，模型草案和人工验证数量均为0。课程标题去除了第一课时、第二课时等表面差异并聚合来源，但“练习、复习、实验、活动”仍作为不同教学功能保留。该层不是最终原子知识图谱。

### 2.1 官方课标资料现状

已从教育部官方入口下载《义务教育课程方案（2022年版）》和16门义务教育课程标准，共17份PDF、1852页；另登记3份江苏省教育厅官方实施文件，合计20个官方来源。教育部PDF为扫描版，普通文本解析为空，因此采用本机OCR逐页提取并保存页码、文件SHA-256和来源URL，原PDF与OCR文本均不上传云端。

国家课程标准是学科核心素养、课程目标、内容要求和学业质量的权威能力骨架。江苏省文件不替代国家学科课标，主要补充教材选用、课程实施和实验教学边界。系统必须分别保存`national_standard`与`jiangsu_implementation`来源角色，不得把地方实施报道误写成新的学科能力标准。

## 3. 六层知识体系

### 3.1 课程标准层

课程标准层定义学段核心素养、内容领域、学业质量要求和阶段目标，是完整性审计的最高优先级来源。首批采用教育部《义务教育课程方案和课程标准（2022年版）》及16门课程标准。标准只定义应达到的能力，不用于推断学校当天教学事实。

### 3.2 地区与教材层

地区与教材层保存江苏省教学用书目录、南京学校实际教材版本、年级、上下册、单元和章节顺序。江苏省目录只能证明允许选用范围；具体孩子的教材版本仍须由家庭实物目录、学校通知或作业证据确认。

### 3.3 课程证据层

课程证据层保存苏e优课课程元数据、转录、本地视频路径和来源哈希。视频不复制到App数据库，转录建立本地全文索引。完整转录、音视频和本地路径不得上传云端。

### 3.4 原子知识与能力层

每个原子对象包含：知识点或能力名称、学科、年级、学期、教材单元、对象类型、学习目标、必要前置、关键概念、方法步骤、表征方式、常见错误、易混点、掌握标准、诊断蓝图、讲解策略、迁移目标、来源证据和成熟度。

对象类型至少包括`concept`、`procedure`、`reasoning`、`representation`、`language_function`、`experiment`、`reading_strategy`、`writing_skill`、`physical_skill`和`value_judgement`。不同学科不得套用统一的数学式模板。

### 3.5 学生证据与掌握层

学生状态只接受可追溯证据：独立作答、过程说明、订正、迁移题、延迟复测、口语或作品量表。课程口述、视频命中、行为观察和模型推断不能直接提高掌握概率。每次状态变化保存旧值、新值、证据、算法版本和下次复测时间。

### 3.6 教学策略层

教学策略层把已验证知识对象转成可执行的提示阶梯、例题选择、表征建议、复习间隔和错误干预。策略效果按孩子、学科和知识类型评估；安全、隐私、答案边界和家长规则不参与自动优化。

## 4. 内化流水线

```text
来源登记与许可判断
-> 年级、学科、版本、学期和单元标准化
-> 课程主题聚合与重复检测
-> 按单元批处理抽取原子知识与能力
-> 前置、易错点、掌握标准和诊断蓝图生成
-> 课标覆盖对齐与缺口检测
-> 来源冲突、越级内容和转录错误检查
-> 模型草案
-> 人工或高可信规则验证
-> 发布知识版本
-> 计划、诊断、讲题和复习消费
```

### 4.1 模型批处理

按“年级+学科+教材版本+学期+单元”组成批次。输入只包含课程标题、课程描述、章节路径、经过长度限制的转录片段，以及按学段和关键词召回的官方课标页；每个批次最多8个课程主题、每个主题最多600字。模型必须输出结构化JSON，不允许自由文本直接入库。

模型输出至少包含：原子能力名称、类型、可观察学习目标、前置能力名称、常见错误、掌握标准、三档诊断蓝图、适龄讲解策略、迁移目标、来源主题ID、课标对齐和置信度。课标对齐必须包含`来源ID:页码`、该页OCR中存在的短原文、要求类型、适用学段、规范化要求与可观察结果。来源主题ID不在输入集合、课标引文不在所给页面、字段超长、对象数量异常、把练习答案写成知识点或无法解析时，整批拒绝入库。

批处理任务和批次状态写入SQLite，可在服务重启后恢复。模型只生成`model_drafted`草案；家长或教研审核“通过”后，能力、课标要求和课程对齐才一起进入`verified`。如果该学科已有官方标准但草案没有课标对齐，界面禁止审核通过。

在模型内化之前，系统先为每个`source_structured`课程主题生成候选审计状态。题名、单元关键词和学段能命中对应学科官方页面时记为`candidate`并保留页码、匹配词、置信度和算法版本；有该学科标准但无法可靠命中时记为`unresolved`；没有对应学科标准时记为`no_subject_standard`。三种状态都覆盖到每个课程主题，但只有候选召回意义，不是正式课标对齐。正式关系仍必须经过模型原文锚定和人工审核。

当前全库审计结果为3043个`candidate`、646个`unresolved`、39个`no_subject_standard`，合计3728个课程主题。39个缺标准主题全部来自小学或初中综合实践活动；系统保留缺口，不用课程方案中的泛化页面冒充具体学科要求。

### 4.2 去重与关系解析

同年级、学科、版本和学期内，标题相似、目标等价且来源单元一致的对象合并；跨学期同名对象保留进阶层级。前置关系先保存为待解析名称，再与现有对象匹配；形成环路、跨年级倒置或来源不足时进入冲突队列，不自动发布。

### 4.3 成熟度

| 成熟度 | 含义 | 可用范围 |
|---|---|---|
| `source_structured` | 从课程元数据整理出的主题 | 搜索、低置信课堂候选、公开课程参考 |
| `model_drafted` | 模型完成原子化和教学属性草案 | 家长预览、影子检索、缺口分析 |
| `verified` | 经规则交叉检查并由家长、教研人员或权威结构确认 | 诊断、计划、掌握度、复习和稳定讲题 |
| `conflicted` | 来源、版本或关系冲突 | 隔离，不进入孩子流程 |
| `retired` | 旧课标、旧版本或被替代对象 | 仅用于历史证据回放 |

## 5. App能力消费

### 5.1 每日计划

计划器把已确认作业映射到`verified`知识对象，结合掌握概率、截止时间、认知负荷、遗忘曲线和长期目标安排任务。只有`source_structured`或`model_drafted`命中时，任务显示为“待确认课程主题”，不生成确定性补弱结论。

### 5.2 学习诊断

诊断必须基于掌握标准和诊断蓝图生成或选题。客观题需要程序核验或已验证答案；开放题需要量表。一次正确只形成证据，不直接等同于稳定掌握；至少结合变式和延迟复测。

### 5.3 讲题与陪学

讲题优先检索已验证知识对象，再补充最多2段公开课程参考。课程转录可能有识别误差，不能覆盖题目原文。孩子的问题与课程无强学科锚点时返回无匹配，不为了提供内容强行召回。

### 5.4 家长报告

报告显示已验证知识点的证据变化、待确认课程主题、学习策略效果和知识缺口。不得把课程观看、口述命中或摄像头行为写成“已经掌握”或“学习态度有问题”。

## 7. 质量门禁

1. 覆盖门禁：每个目标年级、学科和学期必须对齐课标领域，输出已覆盖、部分覆盖、无来源和版本冲突。
2. 原子性门禁：一个对象应能用一组一致的掌握标准评估；同时包含多个独立能力时必须拆分。
3. 可诊断性门禁：每个发布对象至少有1个可观察掌握标准和3档诊断蓝图。
4. 来源门禁：每个结论至少关联一个课程标准、教材锚点或课程证据；模型常识不能成为唯一来源。
5. 关系门禁：前置图不得成环，跨年级关系必须符合进阶逻辑。
6. 召回门禁：人工标注查询集评估Top-1和Top-3命中，错误强召回率单独统计。
7. 教学门禁：按学科评估准确性、年龄适配、答案泄露、转录污染和错误纠正能力。
8. 发布门禁：`model_drafted`数量不能被UI或报告表述为已验证知识点。

## 8. 实施顺序

第一阶段完成覆盖矩阵、课程主题聚合、成熟度和来源映射。第二阶段按四年级语文、数学、英语及初三语文、数学、英语、物理、化学建立模型批处理内化与审核流。第三阶段导入2022年版课程标准并执行覆盖差异分析。第四阶段让计划、诊断、讲题和复习只消费已验证对象。第五阶段扩展PET、目标竞赛、南京考试资料和学习科学策略，并持续用真实孩子证据校准。

截至2026-08-27，课程主题聚合、官方课标登记/OCR/全文检索、可续跑内化任务、严格JSON校验和家长审核工作台已经实现。真实千问内化尚未运行，`verified`能力仍为0；现有计划、诊断、讲题和复习也尚未统一切换到新能力ID。因此前三阶段属于“代码与本地数据管线可用”，第四、第五阶段仍是研发任务，不能表述为知识库已经全部内化。

## 9. 验收标准

- App可展示目标孩子每门学科上下学期的来源覆盖、结构化主题、模型草案、已验证对象和缺口数量。
- 同一课程多课时不会重复形成多个等价主题，练习、复习、实验和活动的教学功能不会被错误合并。
- 任一已验证原子对象可追溯到课标、教材或课程证据，并具备前置、易错点、掌握标准和诊断蓝图。
- 计划、讲题、诊断、复习和报告使用同一知识对象ID和知识版本。
- 删除语料库后，其课程、主题、映射、模型草案和全文索引均清除，原始240GB视频不受影响。
- 没有强锚点、存在来源冲突或只有模型草案时，App明确降级，不产生确定性掌握结论。
