# 智能错题本与掌握闭环PRD

日期：2026-08-27  
版本：v1.0  
状态：全量研发权威范围

## 1. 产品目标

错题本不是保存题目图片的收藏夹，也不是把原题反复做对。系统需要从每次错误中形成可验证的薄弱点假设，选择合适的补救内容和变式题，并通过独立作答、迁移题和延迟复测判断孩子是否真正掌握。

完整闭环为：

```text
纸面作答或系统作答进入统一账本
-> 题干与实际作答事实自动识别；仅在歧义时请孩子澄清
-> 老师批改、版本化标准答案或智能体冻结规则判定正误
-> 合格错误进入错题；合格正确进入独立复测；无权威保持待评分
-> 错因与薄弱点诊断
-> 前置知识或方法补救
-> 同构题验证
-> 表征变化与易混辨析
-> 48小时和7天延迟复测
-> 掌握归档
-> 后续再错时复发并重新诊断
```

## 2. 核心原则

1. 孩子不承担判断对错或“是否需要订正”的责任；孩子的确认只用于纠正系统读到的题干、实际作答和题目归属。
2. 一道错题只产生薄弱点假设，不直接把孩子判定为不会某个知识点。
3. 必须保存原题、孩子原作答、草稿、提示、订正和后续变式之间的证据关系。
4. 重复的是能力和方法，不是无限重复同一道题或只替换数字。
5. 连续失败意味着当前教学策略或前置能力不合适，系统应退回讲解、降阶或暂停，而不是继续加题。
6. 错误按知识价值、复发频率、考试重要度和补救成本排序，不把全部错题都变成高强度训练。
7. “已订正”不等于“已掌握”；“原题记住答案”不等于“能够迁移”。
8. 错题本的最终目标是减少同类错误和提示依赖，不以错题数量、刷题数量或使用时长作为成功指标。

## 3. 错题来源

### HSC-ERR-001 自动与主动收集

错题可以来自：

- 高拍仪拍摄的作业、练习册、试卷和订正本。
- AI Tutor会话中的错误或低置信作答。
- PET客观题、写作、口语任务和朗读覆盖检查。
- 竞赛数学诊断和日常强化题。
- 48小时、7天或更长期复测中的再次错误。
- 孩子口述“这题我不会”“老师说这里错了”。
- 家长手动添加或补充老师批改结果。

自动检测结果先进入`待评分`。系统先核对题目区域、学科、原作答和题目归属，再由且仅由三类权威判定正误：老师已批改且与题块严格绑定的标记或分数、孩子自主拓展练习对应版本的标准答案、智能体出题时冻结的答案与评分规则。孩子不确认“是否确实错误”；只有题干、实际作答或题目归属存在歧义时，才请孩子澄清事实。OCR、题目绑定或评分权威不足时，不得静默写入错题本。

三类流程必须使用同一个作答账本，但评分来源和失败处理不同：

| 场景 | 正误权威 | 系统动作 | 孩子可以纠正什么 |
|---|---|---|---|
| 老师批改的作业或试卷 | 与题块严格绑定的勾、叉、分数或老师批注 | 本地识别并核对题块与作答；判错后自动建错题，判对后记正确作答 | 题干、自己实际写的答案、题号或是否属于本人 |
| 自主拓展的习题 | 与书名、版次、册次、页码和题号绑定的版本化标准答案或量表 | 找到严格同题答案后评分；答案版本冲突时保持待评分 | 题目来源、题干、自己实际作答；不能用口头“对/错”替代答案 |
| 智能体生成的练习 | 题目展示前冻结且与题目版本绑定的答案或评分量表 | 提交后自动评分；冻结规则缺失、变化或撤回时不得继续沿用旧分数 | 自己实际回答、系统是否听错；不能要求模型临时补写答案后倒推评分 |

孩子说“我做对了”“这不是错题”或“这是错题”时，只记录为评分异议并触发权威复核，不立即创建、确认或删除错题。孩子说“题干读错了”“这不是我做的”“我当时写的是……”时，作为可追溯事实修订处理；修订会使旧评分及其派生诊断、复习义务重新核对。

### HSC-ERR-002 去重与合并

系统按题目指纹、来源图片区域、学科、知识节点、题型结构和原作答判断重复。重复拍摄同一题只新增来源或尝试，不创建多个错题卡。不同题目但暴露同一薄弱点的，保留独立题目并聚合到同一薄弱点簇。

## 4. 错题状态机

```text
captured
-> awaiting_confirmation
-> diagnosing
-> remediating
-> near_transfer
-> mixed_transfer
-> delayed_verification
-> fragile
-> mastered

任一阶段 -> excluded
fragile/mastered -> relapsed -> diagnosing
```

| 状态 | 含义 |
|---|---|
| `captured` | 已采集，尚未完成质量检查 |
| `awaiting_confirmation` | 兼容字段名；业务含义为等待核对题干/原作答事实或等待合格评分权威，不要求孩子判断正误 |
| `diagnosing` | 正在收集错因和薄弱点证据 |
| `remediating` | 正在补前置知识、概念或方法 |
| `near_transfer` | 使用同结构不同表面的题目验证 |
| `mixed_transfer` | 与易混题型交错，验证选择方法的能力 |
| `delayed_verification` | 等待48小时、7天或模型计算的复测 |
| `fragile` | 当前会做但稳定性或迁移证据不足 |
| `mastered` | 已满足该错题的掌握退出门槛 |
| `relapsed` | 归档后再次出现同类错误 |
| `excluded` | 题目错误、识别错误、超出范围或家长排除 |

所有状态转换保存原因、证据、算法和策略版本，支持重放和人工纠正。

## 5. 错因与薄弱点诊断

### HSC-ERR-010 错因候选

错因只能作为带置信度的候选：

- 概念或事实知识缺失。
- 前置知识不稳。
- 题意、条件或问题目标理解错误。
- 方法选择错误或不会启动。
- 计算、操作、符号、单位或书写执行错误。
- 记忆提取失败。
- 会做同类题但不能迁移到新表征。
- 偶然失误或当前证据不足。

系统不使用“粗心”“笨”“不认真”作为错因标签。“偶然失误”也必须经过后续快速检查，不能用来跳过知识诊断。

### HSC-ERR-011 证据采集

诊断至少选择一种补充证据：让孩子复述题意、说明第一步、指认自己原来错在哪里、展示草稿、完成一道诊断小题或辨析两个易混方法。模型输出必须分开显示孩子原话、可观察证据和系统推断。

### HSC-ERR-012 薄弱点聚合

每道错题映射一至三个主要知识或能力节点，同时记录前置节点、题型和误区。系统按最近时间、重复次数、独立程度、题目难度和迁移表现聚合薄弱点，输出：

- `suspected`：单次或低质量证据。
- `emerging_pattern`：不同题目出现至少两次一致证据。
- `confirmed_gap`：跨题型或延迟复测仍表现不稳。
- `improving`：补救后近期证据明显改善。
- `stable`：满足掌握门槛并通过延迟验证。

薄弱点状态进入统一知识状态模型，错题本不维护另一套互相矛盾的掌握分数。

## 6. 针对性强化

### HSC-ERR-020 补救路径

系统根据错因选择最短有效补救：

- 概念缺失：使用教材定义、反例、图示或操作活动重新建立概念。
- 前置薄弱：暂时退出当前题，先完成前置能力的小诊断和补救。
- 审题困难：训练条件标注、问题改写和数量关系表达。
- 方法选择：比较两个候选方法及其适用条件。
- 执行错误：加入步骤核对、估算、符号或单位检查。
- 记忆提取：主动回忆和间隔复习，不立即反复重读答案。
- 迁移失败：改变题目表征、情境或信息顺序。

讲解结束后必须让孩子做出动作：复述、写关键一步、选择方法、解释反例或独立完成新题。只说“听懂了”不能完成补救。

### HSC-ERR-021 变式阶梯

强化按能力证据逐级推进：

1. `repair_check`：检查刚才补救的关键一步。
2. `near_transfer`：同一深层结构，改变数字、措辞或表面情境。
3. `representation_transfer`：在文字、图表、公式、几何图或生活情境之间转换。
4. `discrimination`：与相似但方法不同的题型混合，要求先判断用什么方法。
5. `far_transfer`：在新场景中组合使用该能力，只用于重要知识点和高能力目标。
6. `delayed_recall`：离开即时记忆线索后进行48小时、7天和动态间隔复测。

题目必须绑定知识节点、目标错因、难度、变式层级、来源、答案或量表以及验证状态。模型生成题在展示前必须完成结构、答案、难度和重复性检查；数学题继续使用独立核验链。

### HSC-ERR-022 练习剂量与退出

单个错题簇默认一次安排一至三道有效题。连续两次失败或请求详细提示时，停止同级追加题并回到诊断或补救；孩子明显疲劳、拒绝或超过当晚预算时延期。系统不得出现“做不对就无限加题”的惩罚循环。

### HSC-ERR-023 计划优先级

错题簇进入每日计划时综合考虑：次日考试或作业关联、知识节点重要度、复发次数、前置影响、遗忘风险、最近独立表现、预计补救时长和孩子当晚负荷。计划器优先安排“重要且当前能够通过短时补救取得进展”的错题，不以最旧、最多或最难作为唯一排序。

同一薄弱点的多道错题应合并成一次强化任务，并限制同科连续强化量。初三临近考试的核心错题可提高紧迫度；四年级PET和竞赛数学错题仍受每周专项预算约束，不能挤压睡眠和校内必须任务。

## 7. 掌握判定

### HSC-ERR-030 分级退出门槛

掌握门槛由错误类型和重要度决定：

| 类型 | 最低退出门槛 |
|---|---|
| 偶然执行错误 | 能说明错误并独立完成一次快速检查；必要时48小时抽查 |
| 方法或步骤错误 | 独立订正、两道近迁移至少一题无提示正确、48小时复测 |
| 概念或前置知识缺失 | 能解释概念、近迁移、辨析题、48小时和7天独立复测 |
| 迁移失败 | 表征变化题和混合辨析题独立正确，再完成延迟复测 |
| 高频或考试核心错误 | 上述门槛加一次后续交错练习，归档后继续低频抽查 |

实际算法同时检查正确性、提示等级、用时异常、过程说明、迁移层级、延迟间隔和状态不确定度。未达到门槛时显示“正在变稳”或“待延迟验证”，不显示“已掌握”。

### HSC-ERR-031 复发

已掌握错题簇再次出现相同知识节点和错因时转为`relapsed`。系统保留历史掌握证据，分析是遗忘、题型迁移、前置能力还是偶然执行问题，并重新计算复测间隔；不得简单清零孩子之前的进步。

## 8. 孩子端功能

错题本作为一级入口，包含四个工作视图：

| 视图 | 内容 | 主要动作 |
|---|---|---|
| 待评分 | 新采集题目、原作答、识别结果和评分权威状态 | 修正识别事实、排除无效记录、补齐标准答案或等待老师批改 |
| 今日强化 | 最高价值的少量错题簇和预计时间 | 开始补救、查看原题、继续任务 |
| 待复测 | 到期时间、知识点和上次进展 | 开始复测、合理延期 |
| 已掌握 | 归档题目、掌握证据和最近抽查 | 搜索、回看方法、查看成长 |

错题详情同屏显示原题、原作答、草稿、错因假设、关联知识点、补救路径、变式进度、下一次复测和“为什么还没归档”。孩子可以说“这不是我不会”“题目识别错了”“我当时看错条件了”，系统保存纠正并重新诊断。

界面避免红色惩罚式设计和“又错了”语言。Agent使用“找到一个可以变强的点”“我们先确认卡在哪一步”等表达，但不能用空泛鼓励掩盖真实错误。

## 9. 家长端功能

家长中心新增错题与薄弱点视图：

- 各学科新增、待评分、强化中、待复测、已掌握和复发数量。
- 高频薄弱点、对应题目、证据数量、最近趋势和状态不确定度。
- 从薄弱点下钻到原题、孩子作答、提示、订正、变式和延迟复测。
- 今日错题训练为什么安排、预计多久、何时应停止。
- 允许排除错误题目、修正知识点、确认老师批改和降低某类训练优先级。
- 家长沟通建议强调过程和策略，不比较错题数量或要求一次性清空。

日报只报告当天实际处理和待处理事实；周报、月报展示同类错误减少、独立正确率、迁移和复发趋势，不用“错题减少”单独证明能力提升。

## 10. 数据设计

错题本复用`learning_evidence`、`diagnosis_hypothesis`、`knowledge_node`、`mastery_state`和复测任务，新增以下聚合对象：

| 对象 | 作用 |
|---|---|
| `mistake_case` | 一张可追踪错题卡，引用原始学习证据和当前状态 |
| `mistake_occurrence` | 同一错题簇的每次出现、来源、作答和确认 |
| `mistake_capture_candidate` | 一页OCR按题切分后的可编辑候选、区域、置信度与处理状态 |
| `mistake_capture_candidate_event` | 候选生成、修订、跳过和保存事件，用于幂等恢复与后续重建 |
| `mistake_cluster` | 跨题目聚合的知识节点、题型和错因模式 |
| `remediation_step` | 补救动作、策略、结果和孩子反馈 |
| `variant_item` | 变式层级、来源、答案、验证和目标知识点 |
| `mistake_mastery_gate` | 当前退出门槛、已满足证据和缺失证据 |
| `mistake_status_event` | 状态转换、原因、版本、撤销和人工纠正 |

题目图片是可选本地证据；即使原图按家庭设置删除，错题卡仍保留题目结构化摘要、来源位置、孩子作答和状态事件。删除错题时同步重建受影响的薄弱点与掌握派生状态，不能留下孤立引用。

## 11. 服务边界

- `MistakeCaptureService`：采集、OCR关联、质量检查、题干/本人作答/题目归属事实核对和去重；不接受孩子对正误的判断。
- `MistakeDiagnosisService`：错因候选、证据补充、知识映射和薄弱点聚合。
- `RemediationService`：补救策略、前置能力跳转和变式阶梯。
- `MistakeMasteryService`：退出门槛、复测调度、复发和状态重建。
- `VariantValidationService`：题目结构、答案、难度、重复性和来源验证。

计划器只消费错题服务输出的优先级、预计时长、到期时间和硬约束，不直接读取模型原始回答。知识状态服务只消费已经确认的作答和复测证据。

首批本地API包括：

| 方法与路径 | 作用 |
|---|---|
| `GET /v1/children/{child_id}/mistakes` | 按状态、学科、知识点和到期时间读取错题卡 |
| `POST /v1/mistakes/capture` | 兼容历史导入；新流程先建立作答事实和待评分义务，不直接确认错题 |
| `POST /v1/capture-artifacts/{artifact_id}/mistake-candidates/prepare` | 本地切分一页OCR并幂等生成逐题候选 |
| `GET /v1/children/{child_id}/mistake-capture-queues` | 读取刷新或重启后仍待处理的拍题队列 |
| `PUT /v1/mistake-capture-candidates/{candidate_id}` | 修订候选题文字并记录事件 |
| `POST /v1/mistake-capture-candidates/{candidate_id}/skip` | 明确跳过正确题或无效候选 |
| `POST /v1/mistake-capture-candidates/{candidate_id}/capture` | 将已核对的题干与实际作答事实保存为待评分记录；不以孩子确认判定正误 |
| `POST /v1/mistakes/{id}/confirm` | 历史兼容接口；孩子端不得调用`confirm`判定正误，只可排除识别错误记录；正式建错题使用合格评分权威 |
| `POST /v1/mistakes/{id}/diagnose` | 提交孩子补充证据并生成错因候选 |
| `POST /v1/mistakes/{id}/remediation-steps` | 记录讲解、前置补救、复述或关键步骤 |
| `POST /v1/mistakes/{id}/attempts` | 提交变式或延迟复测作答和提示情况 |
| `POST /v1/mistakes/{id}/reschedule` | 在计划约束内合理延期 |
| `GET /v1/children/{child_id}/weakness-clusters` | 读取薄弱点、趋势、证据和掌握门槛 |
| `GET /v1/mistakes/{id}/evidence` | 读取原题到归档的可解释证据链 |
| `POST /v1/mistakes/{id}/corrections` | 孩子或家长纠正错因、知识映射和状态 |

所有写接口要求`client_action_id`并保证幂等；任何错题ID都必须与路径或令牌中的`child_id`一致。模型处理中的请求返回持久化任务状态，刷新后可以继续查看进度、错误和重试，不让孩子重新完成已经保存的确认工作。

## 12. AI边界

LLM可以提取题目、生成错因候选、选择讲解表达、生成变式候选和解释学习路径。LLM不能单独确认原题答案、直接把错因写成事实、判定稳定掌握或无限生成练习。

当题目不完整、图片模糊、答案核验冲突、无法映射知识点或生成变式未通过验证时，记录保持待评分或待复核，并提供重新拍摄、事实修订、只记录不训练或补充权威来源路径。家长可以补充“这是哪一本答案册/老师如何批改”的来源事实，但不以主观点击替代答案或评分权威。

## 13. 验收标准

1. 高拍仪采集一张包含多题的试卷后，老师批改题、带标准答案的拓展题和智能体出题分别沿三类权威自动判定；孩子只在识别歧义时澄清事实，正确题不会静默进入错题本。
2. 同一原题重复导入不产生重复卡片，不同题目可以聚合到同一薄弱点。
3. 一次错误只形成假设；多题、迁移或延迟证据才能形成确认薄弱点。
4. 错题可完成诊断、补救、变式、48小时、7天、掌握归档和复发的完整状态流。
5. 连续两次失败后停止同级加题并退回补救，不形成无限练习。
6. 原题记忆正确但辨析或迁移失败时不能判定掌握。
7. 状态、输入和家长修订跨刷新、应用、本地服务和电脑重启保持。
8. 两个孩子的错题图片、知识状态、复测和家长视图严格隔离。
9. 家长可以从薄弱点下钻到全部证据，并看懂为什么安排、为什么未掌握和下一步做什么。
10. 删除、排除或修订错题后，薄弱点和掌握派生状态可以一致重建。
