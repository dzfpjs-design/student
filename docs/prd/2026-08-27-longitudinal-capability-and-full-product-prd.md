日期：2026-08-27  
版本：v1.0  
状态：全量研发权威范围

执行补充：本 PRD 中的全部能力均为最终交付范围。任何纵向切片、阶段版本或首次跑通都只能作为实施里程碑，不得解释为 MVP 范围或产品完成。当前逐项状态、六层完成证据和后续执行顺序统一记录在[完整产品交付总账](../development/FULL_PRODUCT_DELIVERY_LEDGER.md)。

## 1. 文档目的

本文固化家庭学习伙伴的内在能力、孩子端功能、家长端功能和后台能力，作为后续逐项实现、测试和验收的总设计。本文定义的是完整产品范围，不以MVP删除能力；实施阶段可以按依赖关系分批交付，但所有列入本文的能力都必须进入需求追踪表，不能因首个闭环可运行而被默认为完成。

产品服务南京一名初三学生和一名四年级学生。目标不是制造一个会聊天的题库，也不是摄像头监督软件，而是形成一个能够长期积累证据、理解差异、调整教学与陪伴方式，并逐渐减少孩子对Agent依赖的家庭学习伙伴。

## 2. 总体原则

1. 事实、状态、记忆和决策分层。系统不得把模型生成的总结直接当作事实。
2. 不把孩子压缩为单一分数、单一向量或人格标签。
3. 知识掌握只由可追溯学习证据更新；课程命中、课堂口述和行为观察不能直接证明掌握。
4. 行为模型只描述可观察、分场景的模式，不输出懒惰、多动、焦虑等人格或医学结论。
5. LLM负责理解、解释、生成候选和自然交互；确定性规则和专用状态模型负责权威更新。
6. 连续家庭影像和原始环境音不上传云端。云模型只接收完成任务所需的最小文字、结构化状态和必要题目区域。
7. 个性化必须可解释、可纠正、可回滚。孩子和家长的纠正优先于模型推断。
8. 陪伴的长期目标是增强孩子独立性，而不是提高对Agent的依恋或使用时长。

## 3. 能力总架构

```text
本地多模态输入与产品操作
        ↓
不可覆盖的证据事件账本
        ↓
知识状态模型 + 行为习惯模型 + 干预效果模型
        ↓
证据关联的长期记忆与LLM Wiki
        ↓
计划策略 + 教学策略 + 陪伴策略 + 家长建议策略
        ↓
孩子执行与家长反馈
        └──────────────→ 新证据
```

### 3.1 CAP-EVT 证据事件账本

事件账本是全部长期建模的权威事实源。历史事件只追加，不覆盖；派生状态必须能够根据事件和算法版本重建。

每条事件至少包含：

- `event_id`、`child_id`、`session_id`和发生时间。
- 事件类型、来源、上下文和来源对象。
- 观察值、置信度、确认状态和证据质量。
- 设备、模型、知识库、策略和算法版本。
- 是否由孩子确认、家长确认或系统推断。
- 幂等键、修订关系和撤销关系。

首批统一事件域包括：

- 学习事件：作答、提示、订正、复述、变式、复测、作品和任务完成核对。
- 计划事件：生成、确认、改序、缩短、延期、开始、暂停、恢复和完成。
- 行为事件：在座、离座、书写样、停顿样、切换、求助和恢复。
- 干预事件：触发、策略、表达、接受、拒绝、恢复时间、结果和孩子纠正。
- 陪伴事件：孩子主动发起的话题、共同活动、偏好反馈、边界触发和结束方式。
- 家长事件：建议查看、执行、未执行、效果、沟通压力和纠正。

### 3.2 CAP-KNW 知识与能力状态模型

课程、课标和题目必须映射到原子知识与能力节点。每个`child_id + knowledge_node_id`至少维护：

| 状态 | 含义 |
|---|---|
| `mastery_probability` | 当前掌握概率 |
| `memory_stability_days` | 记忆稳定期 |
| `retrievability_now` | 当前可提取概率 |
| `independence_score` | 不依赖提示完成的程度 |
| `transfer_score` | 在变式和新场景中的迁移能力 |
| `evidence_count` | 有效证据数量 |
| `uncertainty` | 状态不确定度 |
| `last_verified_at` | 最近一次有效验证时间 |
| `next_review_at` | 下次复测时间 |
| `algorithm_version` | 状态更新算法版本 |

算法路线：

- 原子能力图谱负责前置、组成、误区、题型、迁移和补救关系。
- 初期采用PFA或个体化BKT思想的可解释更新，逐步替代当前单一规则分数。
- 单词、公式、古诗和事实性知识增加基于难度、稳定性、可提取性的间隔复习状态。
- 题目数量足够后校准题目难度；数据不足时使用教研先验并显示不确定度。
- 深度知识追踪只能在数据量、离线预测、校准度和解释性门禁同时满足后进入影子评估。

证据强度默认顺序为：延迟迁移题独立正确、延迟同类题独立正确、首次独立正确、轻提示后正确、详细提示后正确、看答案后订正。一次答对不能直接变为稳定掌握。

### 3.3 CAP-BHV 行为与习惯状态模型

行为模型按科目、时间、任务类型、难度和家庭情境建立个人基线，首批维度包括：

- 启动：从计划时间到真正开始的延迟。
- 持续：有效学习片段长度和中断频率。
- 恢复：中断或休息后返回任务的能力。
- 计划：预计时间与实际时间的偏差。
- 求助：遇到困难后求助的时机和方式。
- 独立：不依赖Agent提醒和提示完成任务的比例。
- 反思：是否能说明学会、困难和下一步。
- 干预响应：不同提醒方式下的接受、恢复和完成结果。

首版采用按上下文分组的滑动基线、EWMA趋势和学习过程序列；后续在数据充分时增加个体内时间序列和上下文策略比较。输出必须使用“在什么场景下观察到什么趋势”的表达，不允许生成固定性格结论。

### 3.4 CAP-INT 干预效果模型

系统不只记录是否提醒，还必须学习怎样提醒这个孩子更有效。每次干预保存：

- 触发证据和当时上下文。
- 策略类型、提醒强度、表达方式和提醒预算。
- 孩子接受、拒绝、纠正或要求安静。
- 恢复任务所需时间、最终完成结果和后续情绪自述。
- 家长反馈和策略版本。

初期使用保守规则和同一孩子的N-of-1比较；后期只有在样本量、收益指标和安全约束满足时，才允许上下文策略算法进入影子模式。任何策略升级必须经过`draft -> replay_passed -> shadow -> active`，支持自动和家长手动回滚。

### 3.5 CAP-MEM 证据型长期记忆与LLM Wiki

LLM Wiki是可读记忆层，不是权威数据库。它分为：

1. 稳定档案：年级、教材、目标、兴趣、作息和家长确认的长期事实。
2. 情景记忆：近期重要学习与陪伴事件的摘要。
3. 能力档案：每个能力簇的状态、证据、待验证问题和有效教学方式。
4. 策略卡片：具体情景、使用策略、结果和适用边界。
5. 开放假设：需要更多证据验证的解释，不能作为事实消费。
6. 关系记忆：孩子喜欢的称呼、故事角色、共同约定和被孩子纠正过的边界。

每条记忆至少包含`claim`、`memory_type`、`evidence_ids`、`confidence`、`status`、`created_at`、`valid_until`、`model_version`和修订历史。状态仅允许`proposed`、`verified`、`rejected`、`expired`和`superseded`。

LLM只能提出记忆草案和引用证据；确定性校验负责检查孩子隔离、证据存在、矛盾、有效期和禁用标签。检索时只向模型提供当前任务相关的少量记忆，不把全量历史对话塞入提示词。

### 3.6 CAP-POL 决策与计划策略

决策层从任务、到期复测、知识状态、行为基线、长期目标、精力、睡眠和家庭硬约束生成候选行动，再经过约束过滤与排序。

核心评分维度包括：作业紧迫度、预期学习价值、遗忘风险、前置能力、迁移价值、疲劳成本、预计完成概率、长期目标贡献和独立性成本。LLM可以解释和生成候选方案，但不能突破最晚结束时间、家长禁用项、传感器状态和儿童安全规则。

### 3.7 CAP-CMP 陪伴与关系能力

陪伴不是通用闲聊附属功能，而是独立能力线：

- 记得共同经历、偏好和约定，并允许孩子纠正。
- 欢迎回家、学习前热身、休息陪伴、结束庆祝和阶段回顾。
- 自由聊天、共同讲故事、角色扮演、文字或语音小游戏、知识游戏和运动口令活动。
- 有控制地陪玩电子游戏或共同看短视频，但由家庭规则限定内容、总时长和结束条件。
- 根据年龄调整语言、幽默、挑战和解释方式。
- 不索取秘密、不贬低现实关系、不制造唯一朋友感、不以沉默或离开惩罚孩子。
- 主动把成功归因于孩子的努力与策略，并逐步减少不必要提示。

所有共同活动必须有开始、剩余时间、自然结束、继续学习或离开设备的出口。陪伴质量指标不使用总对话时长，而使用孩子主动性、任务恢复、独立完成、边界接受和现实活动转化。

### 3.8 CAP-PRT 家长教练能力

家长建议必须基于当前孩子、当天情境、长期趋势和家长历史反馈生成，不能复用千篇一律的模板。每份建议包含：

- 可核对事实和证据来源。
- 暂定解释及不确定性。
- 一套可直接使用的开场、承接、倾听、协商和结束话术。
- 今天做什么、做多久、停止条件和次日观察点。
- 不要做什么的具体错误示例和可替代表达。
- 家长反馈入口：执行、未执行、效果、压力和补充事实。

## 4. 全量产品功能架构

### 4.1 孩子端首页与Agent外壳

- Windows自动启动、身份切换、继续未完成会话和设备状态。
- 拟人智能体视觉、声音、状态和可打断语音交互。
- 今日任务、到期复测、重要安排和长期目标进度。
- “系统记得什么”和纠正入口，使用适龄语言展示，不显示概率和内部ID。
- 离线、模型忙、设备失败、保存失败和恢复状态。

### 4.2 每日报到与课堂复盘

- 精力、可用时间、固定安排和次日考试采集。
- 自由口述、实时转写、知识候选、老师要求和未知项确认。
- 可以表示无作业、想不起来、稍后补充或跳过。
- 所有未提交内容自动保存并可跨重启恢复。

### 4.3 作业、教材与题目采集

- 高拍仪预览、旋转、裁切、重拍、导入和质量检查。
- OCR提取学科、页码、题号、截止时间和老师要求。
- 题目、草稿、订正和完成证据关联。
- 原图保留状态、删除和失效引用处理。
- 孩子试用期间，高拍仪除页面版本证据外还在本机保留定时诊断图及翻页、作答、判题、入库关键图；将图像引用连到页面、题目、作答尝试、正误结果和评分权威，供漏检、误判和设备故障回放。观察摄像头不适用此留图规则。
- 每次学习结束形成可恢复的本地程序复盘任务，按原图和事件链核查正确题、错题及未判题的处理结果；异常可追溯并形成修复记录，不把图像或模型推断直接当作正确性证据。采样和试用阶段以D-026/D-028为准：试用数据与正式档案隔离，保留原图及判定审计，稳定后经发布门禁仅迁移重核合格证据；试用结果不直接更新正式掌握投影。
- 任意纸面主观题按D-027绑定精确题目、本地原页版本、可逐字核对的分点评分依据和独立已评分样例后冻结量表及校准。依据或校准不足时只给形成性反馈并保持未评分，不由模型共识生成错题或掌握证据。

### 4.4 每日与长期计划

- 校内作业、复测、中考、PET、竞赛数学和习惯训练统一排程。
- 睡眠、固定活动、任务负荷、休息和总时长硬约束。
- 计划方案解释、拖动改序、缩短、延期和重新规划。
- 根据真实用时、完成率、知识状态和接受度调整后续计划。

### 4.5 学习工作台

- 当前任务、下一任务、有效学习时间、休息和完成标准。
- 开始、暂停、继续、完成、延期、拍题、求助和安静模式。
- 崩溃、断网和设备故障后的保存与恢复。
- 主动提醒、孩子纠正和提醒预算可见。

### 4.6 AI Tutor与诊断

- 题目识别、知识点映射、前置能力检查和错因假设。
- 分层提示、孩子复述、草稿检查、方法验证和答案核验。
- 讲解必须同时产生适合朗读的语音稿与结构化板书，从真实语音首帧开始按段显示对应内容。
- 黑板支持标题、关键文字、公式、分步推导、表格、先后/因果关系和检查问题；不把整段语音复制成字幕。
- 孩子插话、说“停一下”或新讲解开始时，立即停止尚未显示的板书，保留已写内容；重启后恢复已保存的完整板书。
- 板书作为独立输出通道执行答案泄露、有害内容和不安全 LaTeX 检查；结构无效时使用本地可见降级板书，不出现空白黑板。
- 即时变式、48小时、7天及模型计算的后续复测。
- 知识掌握、记忆、独立性和迁移状态更新。
- 初三校内与中考、四年级PET和竞赛数学专项工作台。

智能错题本作为AI Tutor与知识状态之间的一级闭环，必须覆盖采集、去重、错因确认、薄弱点聚合、补救、近迁移、表征迁移、混合辨析、延迟复测、掌握归档和复发。详细状态机和退出门槛以[智能错题本与掌握闭环PRD](./2026-08-27-mistake-mastery-loop-prd.md)为准。

错题的对错判定只能来自三类可追溯权威：老师已批改且与题块严格绑定的勾/叉或分数；孩子自主拓展练习所绑定的版本化标准答案；智能体出题时与题目一起冻结的答案和评分规则。孩子不承担判定对错或“确需订正”的职责；只有题干、实际作答或题目归属存在不可自动消除的识别歧义时，才用语音请孩子补充事实。证据充分时系统自动建立错题或正确题独立复测，不要求孩子逐题说“确认”。

### 4.7 行为观察与习惯训练

- 本地输出`present`、`away`、`writing_like`、`paused_like`和`unknown`。
- 场景校准、人物基线、影子模式和误提醒反馈。
- 启动、持续、恢复、计划、求助、独立和反思趋势。
- 一次只训练一个可执行习惯，包含目标、提示、时长、结果和复盘。
- 孩子与家长均可纠正错误事件或解释情境。

### 4.8 陪伴生活

- 日常欢迎、自由聊天、共同回忆和适龄情绪承接。
- 原创讲故事、续写故事、角色扮演和知识型小游戏。
- 运动、整理书桌、喝水和休息等离屏共同活动。
- 家庭许可下的电子游戏或视频陪伴计时、内容边界和自然结束。
- 依恋边界、现实关系优先和逐步退出机制。

### 4.9 当日结束与成长档案

- 当日复盘、完成摘要、待订正、待复测和次日第一件事。
- 结束后事务提交、报告排队、临时媒体清理和传感器释放。
- 孩子可见的成长时间线：学会的新能力、坚持、独立完成和共同事件。
- 周/月目标进度和适龄解释，不展示人格判断或虚假精确分数。

### 4.10 家长中心

- 两个孩子今日状态、任务、异常、延期、待复测和专项目标。
- 从结论下钻到题目、作答、提示、订正、复测和状态变化。
- 日报、周报、月报、趋势和证据覆盖说明。
- 完整沟通话术、具体行动、时长、停止条件、错误示例和替代表达。
- 建议执行和效果反馈，反向调整后续建议。
- 孩子长期状态、记忆草案、开放假设和纠错历史。
- 家庭规则、陪伴边界、内容范围、最晚结束时间和专项优先级。

### 4.11 知识与内容中心

- 课标、江苏地区资料、教材目录、课程转录、家庭笔记和题目来源管理。
- 课程主题原子化、课标锚定、冲突隔离、人工验证和覆盖缺口。
- PET官方能力蓝图和目标竞赛能力图谱。
- 教学策略、讲解模板、误区、变式和复测模板。
- 所有计划、诊断、讲题和报告统一消费已验证能力ID。

### 4.12 系统、设备与运维

- 摄像头、高拍仪和麦克风绑定、校准、长时测试与释放验证。

## 5. 数据边界与新增对象

现有`learning_evidence`、`mastery_state`、`mastery_update_event`、`child_state_event`、`intervention_record`和策略实验表继续作为基础，不另建旁路。后续数据库迁移应补齐：

| 对象 | 关键内容 |
|---|---|
| `knowledge_state_dimension` | 掌握、稳定性、可提取性、独立性、迁移和不确定度 |
| `behavior_feature_event` | 从产品与观察事件提取的可重建特征 |
| `behavior_state_daily` | 按上下文聚合的基线、近期趋势和证据数量 |
| `intervention_outcome` | 干预后的接受、恢复、完成、纠正和反馈 |
| `memory_note` | 证据型长期记忆、状态、有效期和修订链 |
| `companion_activity` | 陪伴活动、边界、计时、结果和退出方式 |
| `habit_experiment` | 单一习惯目标、策略、周期、结果和复盘 |

原始视频帧只在本地内存中参与事件提取；如为设备或算法校准临时保存短片，必须独立标记、本地加密并按设置自动删除。任何状态和Wiki条目都不能只引用已经删除且无结构化摘要的原始媒体。

## 6. 核心服务与接口边界

后续实现应形成以下服务，不要求拆成独立进程，但必须保持代码和契约边界：

- `EvidenceLedgerService`：统一写入、幂等、修订、撤销和重放。
- `KnowledgeStateService`：更新与重建知识四维状态、遗忘和复测。

所有服务调用必须携带`child_id`和权威会话上下文；派生输出包含证据引用、置信度、版本和降级状态。

## 7. 验收标准

### 7.1 能力验收

- 删除派生状态后，可以从事件账本重建同版本状态，结果一致。
- 同一证据重复提交不会重复提高掌握度或重复形成干预结果。
- 知识状态能区分会做、记得、独立完成和迁移，不用单一正确率替代。
- 行为结论必须展示场景、趋势、证据数量和不确定性，并支持纠正。
- Wiki中的每条非人工稳定事实都能下钻到证据；证据撤销后自动失效或重算。
- 决策记录可以解释为什么安排、为什么提醒和哪些约束否决了候选动作。
- 两个孩子的证据、状态、记忆、策略和报告不可串档。

### 7.2 功能验收

- 孩子可以从自动启动完成报到、复盘、作业、计划、学习、辅导、复盘和结束，不需要开发者解释。
- 所有输入、确认和家长反馈跨刷新、应用重启、本地服务重启和电脑重启保持。
- 摄像头、高拍仪、麦克风、网络和模型失败均有替代路径、重试和恢复。
- 陪伴活动有明确开始、计时、结束和回到现实活动的路径，不制造无限对话。
- 家长能从结论下钻到证据，并直接执行建议、反馈效果或纠正事实。
- 计划、诊断、讲题、复测和报告统一使用已验证知识节点。
- Windows目标电脑、真实摄像头、高拍仪和麦克风完成端到端验证。

### 7.3 AI质量验收

- 学习讲解使用代表性题目集评估正确性、提示泄露、年龄适配、延迟和成本。
- 知识状态以延迟作答预测、校准误差和证据覆盖评估，不以界面是否显示分数验收。
- 行为模型评估误提醒、漏提醒、纠正率和按场景校准，不以摄像头能取流验收。
- 陪伴模型评估依恋诱导、隐私索取、虚假感知、假工具执行、年龄适配和结束边界。
- 家长建议通过真实执行反馈评估可执行性、沟通压力和后续效果。
